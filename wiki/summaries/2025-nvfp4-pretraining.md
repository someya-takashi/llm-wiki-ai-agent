# NVFP4 による大規模言語モデルの事前学習

> 原典: [[translations/2025-nvfp4-pretraining]] ・ `raw/papers/Pretraining Large Language Models with NVFP4.md`
> 著者: NVIDIA
> 2025 年（arXiv:2509.25149）

## 一言まとめ

**12B のモデルを 10 兆トークン、4 ビットで訓練しきった初の公開記録**である。MMLU-Pro で **62.58%（FP8 は 62.62%）** と、FP8 のベースラインにほぼ一致した。ただしそれは NVFP4 という形式だけの手柄ではなく、**4 つの技法を全部載せて初めて成立する**——どれか 1 つ外すと収束が悪化し、全部外すと訓練は早期に発散する。

## 背景と問題意識

FP8 訓練は 2023〜2024 年に実用化された（→ [[summaries/2023-fp8-lm]], [[summaries/2024-deepseek-v3]]）。次の一歩が FP4 で、Blackwell では FP8 比で **演算 2〜3 倍・メモリ半減**が見込める。

しかし FP4 は **E2M1**——符号 1・指数 2・仮数 1 ビット——であり、表現できる値は $\pm 0, \pm 0.5, \pm 1, \pm 1.5, \pm 2, \pm 3, \pm 4, \pm 6$ の **16 通りだけ**である。これで訓練を通すのは、FP8 とは質の違う難しさになる。

先行の **MXFP4** は「マイクロスケーリング」——32 要素のブロックで 1 つのスケール係数を共有する——で対処していたが、そのスケール係数は **UE8M0**、すなわち **2 の冪しか取れない**。

### MXFP4 の構造的な無駄（付録 B.4）

これが本論文の最も分かりやすい技術的論点である。あるブロックの最大絶対値が $3+\delta$ だとする。FP4 の最大値 6 へ写したいので $s = amax/6 = 0.5+\delta/6$ が欲しいが、**2 の冪へ切り上げると $s=1$ になる**。するとスケール後の amax は $3+\delta$ のまま、FP4 では $3$ に量子化される。

結果、**$\pm 4$ と $\pm 6$ という 4 つのサンプルが使われずに死ぬ**。動的範囲も $\log_2(6/0.5)=3.58$ binade のうち $\log_2(3/0.5)=2.58$ binade しか使えず、**ほぼ 1 binade を失う**。16 通りしかない表現のうち 4 つを捨てるのは大きい。

## 提案手法

### NVFP4 の形式 — MXFP4 への 3 つの改良

<figure>

![](../../raw/assets/2025-nvfp4-pretraining/x1.png)

<figcaption>図1: NVFP4 形式で格納された 16×32 の行列。各ブロックは 16 個の FP4 要素（灰色と緑）と 1 つの FP8 スケール係数（黄色）を持つ。各ブロックで最大の大きさを持つ要素（緑）が FP4 の表現可能な最大値へスケールされる。</figcaption>
</figure>

1. **ブロックサイズを 32 → 16 へ**。ブロック内の動的範囲が狭まり、値が FP4 の範囲に収まりやすくなる。
2. **スケール係数を UE8M0 → E4M3 へ**。指数の範囲を譲って仮数ビットを得る。**2 の冪でない小数のスケーリングができる**ようになり、上記の「4 サンプルが死ぬ」問題が消える。
3. **テンソル水準の FP32 スケールを追加**（2 段階スケーリング）。E4M3 でスケール係数を表せるよう、テンソル全体の分布を先に調整する。

結果として、**ブロック内の少なくとも 6.25%（16 要素中の amax）が FP8 に近い精度で符号化される**。MXFP4 は全値を FP4 で持つので、ここが決定的に違う。

### 訓練の方法論 — 4 つの技法

論文の推奨が明快に 4 行にまとまっている。

1. **敏感な線形層をより高い精度に保つ**（ネットワークの 15%、大半は終端に）
2. **Wgrad の入力へ 16×16 の Random Hadamard 変換**
3. **重みは 16×16 の 2D スケーリング、活性と勾配は 1×16 の 1D スケーリング**
4. **勾配には確率的丸め、重みと活性には最近接偶数丸め**

それぞれの理由が異なるのが重要である。

**(1) 層の感度。** すべての線形層を FP4 にすると**訓練が発散する**。感度が高いのは**最後の数ブロック**で、そこは FP4 より広い動的範囲と仮数を要する。付録 E.2 の観察が示唆に富む——**最初の数ブロックを高精度にしても、最後のブロックと組み合わせない限り安定しない**。テンソル分析によれば、最後の層は Wgrad の量子化誤差が大きくなる傾向がある。

**(2) Random Hadamard 変換（RHT）。** 直交行列 $H$ を両オペランドに掛けると $HH^T=I$ で内積は不変のまま、**外れ値がおおよそガウス分布へ再配分される**。ただし本論文は **Wgrad の入力にだけ適用する**——Fprop と Dgrad に適用すると**むしろ品質が劣化する**（RHT 自体が導入する量子化誤差が、外れ値除去の恩恵を上回るため）。行列サイズは 16×16 が最適で、4×4 では損失が増え、128×128 はわずかに良いだけである。

> この技法は本 wiki に既出である。[[summaries/2024-flashattention-3]] の **incoherent processing** がまさに同じ原理（Q と K に同じランダム直交行列を掛けて出力を変えずに外れ値をならす）で、そちらは attention の FP8 化に使われていた。**同じ道具が訓練の FP4 化にも現れている。**

**(3) 2D スケーリング。** これが最も概念的に面白い。スケーリングは**内積の次元に沿って**適用されるが、逆伝播ではテンソルが転置されるので**内積の次元が変わる**。結果、**同じ重みが順伝播と逆伝播で違う量子化表現を持つ**——これは事実上**連鎖律を破っている**（逆伝播が順伝播で使ったのと違う関数を微分している）。重みを 16×16 の 2D ブロックでスケールすると、どちらの向きでも同じ表現になる。**活性は感度が低い**ので 1×16 のままでよい。

**(4) 確率的丸め。** 最近接丸めは系統的なバイアスを生む。確率的丸めは距離に反比例する確率で上下どちらかへ丸めるので**偏りが消える**。ただし**勾配にだけ適用する**——活性や重みに適用すると**発散する**（最近接丸めより量子化誤差そのものは大きくなるため）。

### アブレーション（Figure 4）

12B を 3.43T トークンまで訓練したところから、構成要素を 1 つずつ外す。**どれを外しても収束が悪化する。** 逆に付録 E.1 は、全技法なしの素の方式では**訓練が早期に発散する**ことを示している。確率的丸めのような単独の技法は安定性を改善するが、それだけでは最終的に発散する。

**これは「NVFP4 という形式を使えば 4 ビット訓練ができる」という話ではない。形式は必要条件の一つに過ぎない。**

## 実験結果と知見

### 本命の実行

**12B の Nemotron-H ハイブリッド Mamba-Transformer を 10T トークン。**

- 検証損失: 安定期の相対誤差は**一貫して 1% 未満**、学習率減衰の終盤で **1.5% 強**まで広がる
- MMLU-Pro **62.58 対 FP8 62.62**、GSM8k CoT **92.27 対 89.08**（NVFP4 が上）、MGSM **85.53 対 81.87**（同）
- **例外はコード**: HumanEval+ 57.43 対 59.93、MBPP+ 55.91 対 59.11。論文は「評価のノイズかもしれない」と述べるが**確証はない**

### NVFP4 対 MXFP4（8B・1T トークン）

**MXFP4 の相対誤差 2.5% に対し NVFP4 は 1.5%。** そして最も実務的な数字——**MXFP4 が NVFP4 に追いつくには 36% 多いトークンが要る**（1T に対し 1.36T）。形式の選択が訓練コストに直接効く。

### 終盤だけ精度を上げる（付録 D）

**8.2T トークン（訓練の 18%）から BF16 へ切り替えると FP8 のベースラインに一致する。** 10T（1% 未満）で切り替えてもわずかに劣るだけ。

しかも**損失の隔たりのほとんどは順伝播の量子化から生じている**——順伝播だけを高精度へ戻すと相対誤差 1.5% → 0.5% に回復し、**全計算のわずか 6%** を高精度にするだけで済む。（なお論文は、逆伝播の切り替えで回復したとする先行研究 [^9] とは**逆の結果**を報告している。）

## 限界・批判的視点

- **速度の測定がない。** 論文自身が「本報告は主として実行時の効率やシステム水準の最適化ではなく、アルゴリズムと方法論に関わる」と明記している。**Blackwell の 2〜3 倍という数字はハードウェアの仕様であって、この訓練実行の実測ではない。** 「4 ビットで訓練できる」と「4 ビットで訓練すると速い」は別の主張である。
- **まだ 16% が高精度である。** 目標は「全線形層を量子化すること」であり、現状はそこに届いていない。しかも attention・埋め込み・正規化・オプティマイザ状態・テンソル並列の縮約は最初から対象外。**「4 ビット訓練」の実際の適用範囲は線形層の 84% である。**
- **FP8 ベースラインとの比較が 1 本ずつ。** 12B × 10T の実行は高価なので当然だが、**乱数シードの分散が分からない**。0.04 ポイント差（62.58 対 62.62）を「ほぼ一致」と読むのは、分散が分からない以上は解釈である。
- **コードタスクの劣化が説明されていない。** HumanEval+/MBPP+ で 2.5〜3.2 ポイント落ちているのを「評価のノイズかもしれない」で済ませており、追加の checkpoint 評価をしていない。**4 ビット化がコード生成に固有の影響を持つ可能性は排除されていない。**
- **技法の相対的な寄与が順序依存である。** 付録 E.1 が「**各技法の相対的な恩恵は構成要素を加える順序に依存する**」と明記しており、「どれが一番効くか」は答えられない設計になっている。
- **小規模の結論が大規模に外挿できない。** 論文自身がこれを繰り返し強調する——Hadamard 行列サイズもランダム化も、1.2B では差が出ないのに 12B では出る。**アブレーションの多くが 1.2B で行われている**ので、12B での確認が取れていない結論が混じっている。
- **NVIDIA の自社形式の論文である。** NVFP4 は NVIDIA の設計であり、Blackwell 専用である。MXFP4 との比較は技術的に妥当だが、**MXFP4 はオープンな標準（OCP）である**という文脈は書かれていない。

## 実装・運用上の示唆

1. **「形式」と「方法論」を分けて考える。** NVFP4 は MXFP4 より良い形式だが、それだけでは 10T トークンを通せない。**低精度化の提案を読むときは、データ型の話と訓練レシピの話を分離する。**
2. **量子化は順伝播と逆伝播で一貫させる。** 2D スケーリングの動機——転置で内積の次元が変わると連鎖律が破れる——は、低精度訓練を自作するときに最も見落としやすい落とし穴である。
3. **丸め方式をテンソルごとに変える。** 勾配は確率的丸め、重みと活性は最近接丸め。**一律に決めない。**
4. **終盤だけ精度を上げるのは安い。** 訓練の最後の 18%、しかも順伝播だけ（全計算の 6%）を高精度にするだけで損失の隔たりが埋まる。**低精度訓練の「損失が少し悪い」は、運用上は解決済みの問題に近い。**
5. **層ごとの感度を測る。** 「最後の数ブロックが敏感」は本論文のモデルでの観察であり、一般則ではない。論文自身が「**量子化誤差の指標が、どの層を高精度に残すか決める機構になりうる**」と示唆している——自分のモデルで測る道具立てを持つべきである。
6. **形式の差はトークン数に翻訳される。** MXFP4 は 36% 多いトークンが要る、という表現は、精度の差を**訓練コスト**として読み替える良い型である。

## 用語と略称

- **NVFP4** = NVIDIA の 4 ビット浮動小数点形式。E2M1 の要素・E4M3 の 16 要素ブロックスケール・FP32 のテンソルスケールの 2 段階構成
- **MXFP4** = Microscaling FP4。E2M1 の要素・UE8M0（2 の冪のみ）の 32 要素ブロックスケール
- **E2M1 / E4M3 / UE8M0** = 指数 2・仮数 1 / 指数 4・仮数 3 / 符号なし指数 8・仮数 0（2 の冪のみ）
- **microscaling（マイクロスケーリング）** = 少数の要素からなるブロックごとに 1 つのスケール係数を共有する方式
- **binade** = 2 の冪 1 つ分の区間（$[2^n, 2^{n+1})$）。動的範囲の単位
- **amax** = absolute maximum（ブロックまたはテンソル内の最大絶対値）
- **Fprop / Dgrad / Wgrad** = 順伝播の GEMM / 活性の勾配の GEMM / 重みの勾配の GEMM
- **RHT** = Random Hadamard Transform（ランダム符号ベクトルを掛けた Hadamard 行列による直交変換。外れ値をならす）
- **stochastic rounding（確率的丸め）** = 距離に反比例する確率で上下いずれかへ丸め、系統的なバイアスを消す方式
- **2D scaling** = 重みを 16×16 のブロックでスケールし、順伝播と逆伝播で同じ量子化表現を保つ方式
- **WSD** = Warmup-Stable-Decay（学習率を大部分一定に保ち、終盤で減衰させるスケジュール）
- **Nemotron-H** = NVIDIA の Mamba-Transformer ハイブリッドのモデルファミリ
- **Tensor Core** = NVIDIA GPU の行列積専用演算ユニット
