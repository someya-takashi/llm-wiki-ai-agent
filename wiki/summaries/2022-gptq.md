# GPTQ: 生成事前学習トランスフォーマのための正確な訓練後量子化

> 原典: [[translations/2022-gptq]] ・ `raw/papers/GPTQ_ Accurate Post-Training Quantization for Generative Pre-trained Transformers.md`
> 著者: Elias Frantar, Saleh Ashkboos, Torsten Hoefler, Dan Alistarh（IST Austria / ETH Zurich / NeuralMagic）
> 2022 年（arXiv:2210.17323）・ICLR 2023

## 一言まとめ

**それまで「1 億パラメータ規模でしか使えない」とされていた二次情報ベースの正確な量子化を、3 つのアルゴリズム的工夫で 3 桁高速化し、1,750 億パラメータのモデルに 4 GPU 時間で適用できるようにした論文**である。結果として **OPT-175B が A100 1 枚に収まり**、専用カーネルで **FP16 比 3.25 倍（A100）／4.5 倍（A6000）のレイテンシ削減**を得た。低ビット重みのみ量子化の事実上の標準になった。

## 背景と問題意識

2022 年当時、1,000 億超のモデルに適用できた量子化は**最近接丸め（RTN）** の変種だけだった。GPTQ 論文は先行研究をこう総括する——「ZeroQuant・LLM.int8()・nuQmm はいずれも量子化の粒度（ベクトル単位など）は注意深く選ぶが、**巨大モデルで許容可能な実行時間を保つために、結局は重みを最近接へ丸めているだけである**」。

より正確な手法（AdaRound、BRECQ、AdaQuant、OBQ）は存在したが、**計算量が入力サイズに三次で効く**ため桁違いに大きいモデルには使えない。ZeroQuant は 1.3B に 3 時間かかっており、線形外挿すれば 175B には数百時間（数週間）になる。

問題は明快だった。**「正確だが遅い」手法を、精度を落とさずに 3 桁速くできるか。**

## 提案手法 — OBQ を 3 段階で作り直す

土台は **OBQ**（Optimal Brain Quantization）。層ごとに $\arg\min_{\widehat{W}} \lVert WX - \widehat{W}X\rVert_2^2$ を解き、重みを 1 つずつ量子化しては、その誤差を補償するよう残りの重みをヘッセ行列の情報で更新していく。実行時間は $O(d_{\text{row}}\cdot d_{\text{col}}^{3})$。

### ステップ 1: 任意順序という着眼（計算量を落とす）

OBQ は「次に量子化すると誤差が最小になる重み」を貪欲に選ぶ。GPTQ の観測は、**この貪欲な順序の利点が、大きく重くパラメータ化された層ではほとんど消える**というものである（個々の誤差が大きい重みが減る効果が、それらが終盤——補償に使える未量子化の重みがもう残っていない時点——で処理されることで打ち消される）。

ならば**全行を同じ順序で量子化してよい**。すると未量子化集合 $F$ と $\mathbf{H}_F^{-1}$ が全行で共通になる（$\mathbf{H}_F$ は層入力にしか依存せず、重みには依存しないため）。逆行列の更新が**重みごと $d_{\text{row}}\cdot d_{\text{col}}$ 回から、列ごと $d_{\text{col}}$ 回**へ減り、計算量は $O(\max\{d_{\text{row}}d_{\text{col}}^{2}, d_{\text{col}}^{3}\})$ になる。**$\min\{d_{\text{row}}, d_{\text{col}}\}$ 倍の削減**で、大きなモデルでは数桁に相当する。

### ステップ 2: 遅延バッチ更新（メモリ帯域律速を外す）

計算量を落としても実際には速くならない。**計算対メモリアクセス比が低い**からである——巨大な行列の全要素を、要素あたり数 FLOP で更新する。これは GPU の演算器を使えず、メモリ帯域で詰まる。[[llm-inference-optimization]] で繰り返される「FLOPs を減らしても wall-clock は減らない」の一例である。

着眼は「**列 $i$ の最終的な丸めは、その列への更新にしか影響されない**」こと。だから更新を **$B=128$ 列単位でまとめ**、ブロック内では $\mathbf{H}^{-1}$ の $B\times B$ 部分だけを触り、ブロックが終わってから全体を一括更新する。理論計算量は変わらないが、**実測で 1 桁速くなる**。

### ステップ 3: コレスキー再定式化（数値的に壊れないようにする）

$\mathbf{H}_F^{-1}$ が**不定値（indefinite）** になると、アルゴリズムは残りの重みを誤った方向へ積極的に更新し、その層の量子化が任意に悪くなる。**この確率はモデルサイズとともに上がり、数十億パラメータを超えると少なくとも数層でほぼ確実に起こる**。

小さいモデルなら減衰（$\mathbf{H}$ の対角に平均対角値の 1% を加える）で足りるが、大きいモデルには不十分。ここで気付くのは、**必要なのは $\mathbf{H}_{F_q}^{-1}$ の行 $q$ の対角以降の要素だけ**だということ。式 (3) による行除去は本質的にコレスキー分解に対応するので、**最初に一度コレスキー分解で必要な情報をすべて前計算しておけばよい**。数値的に安定になり、おまけに最適化されたコレスキーカーネルで速くもなる。

3 つ合わせて Algorithm 1 の 10 行程度の擬似コードになる。

## 実験結果と知見

### 実行時間

単一 A100 で、OPT-13B が 20.9 分、OPT-175B が **4.2 時間**、BLOOM-176B が 3.8 時間。**モデル全体を一度に GPU へ載せる必要はない**——6 層ずつのトランスフォーマブロックを順に読み込み、量子化済みブロックへ入力を通し直しながら進む（これ自体が無視できるコストで目立った精度改善をもたらす）。

### 精度

OPT-175B の WikiText2 で、FP16 8.34 に対し **GPTQ 4 ビットは 8.37（劣化 0.03）、RTN は 10.54**。3 ビットでは RTN が 7.3e3 と完全に崩壊するのに対し GPTQ は 8.68 を保つ。BLOOM も同傾向で差はやや小さい。

**「大きなモデルほど量子化しやすい」**という傾向が観測されている（Figure 1）。圧縮が最も必要なのが大きなモデルなので実用上は朗報である。ただし **OPT-66B だけが例外**で、脚注が理由を示唆している——「このモデルは初期層に**死んだユニット（dead units）** の割合が大きく、それが圧縮を難しくしている可能性がある」。付録のゼロショット結果でも OPT-66B の異常は全タスクで再現する（4 ビット RTN で LAMBADA が 74.93 → 13.08）。

### 極端な量子化

グループ化を組み合わせると 2 ビット台が実用域に入る。OPT-175B で g128（約 2.2 ビット）が PPL 9.58、g32（約 2.6 ビット）が 8.94。さらに**グループサイズ 8 なら三値（-1, 0, +1）量子化が成立し、WikiText2 PPL 9.20（FP16 8.34 から 1 ポイント未満の低下）**。グループ化と GPTQ は相性が良い——グループのパラメータを各層の量子化の途中で、常に最新の更新済み重みを使って決められるからである。

### 実用的な高速化 — ここが最も誤読されやすい

3 ビットの OPT-175B は 63GB（埋め込みと出力層は FP16 のまま）＋ KV cache 約 9GB で、**A100 1 枚（80GB）に収まる**。FP16 なら 5 枚、LLM.int8() なら 3 枚が要る。

そのうえで**「量子化行列 × 完全精度ベクトル」積カーネル**を書き、必要になった時点で重みを動的に逆量子化する。これで A100 でトークンあたり 230ms → 71ms（3.24 倍）、A6000 で 589ms → 130ms（4.53 倍）。通信コストは 8 GPU でも総実行時間の 5% 未満なので、**高速化はほぼすべてカーネルによるもの**である。

**この高速化の出所は演算ではない。** 論文は 2 か所で明記している——「我々の手法は**メモリ移動の削減**から高速化を得ているのであって、計算量の削減をもたらすものではない」「主流のアーキテクチャでは混合精度オペランド（FP16 × INT4）へのハードウェア支援が欠けているため、**実際の乗算については高速化を提供しない**」。バッチサイズ 1 の生成推論が行列-ベクトル積でメモリ律速だからこそ効く手であり、大バッチの計算律速な場面では適用できない（その場合は行列を展開してから通常の行列積をすればよく、A100 で 1.5ms 未満のオーバーヘッドで済む、とも書いてある）。

## 限界・批判的視点

- **活性の量子化がない。** 対象とする場面ではボトルネックでないという理由だが、これは W8A8 の路線（→ [[summaries/2022-smoothquant]]）と狙いが違うことを意味する。
- **キャリブレーションセットへの過適合**が後に批判される。C4 から 128 個の 2048 トークン断片を使い、**タスク固有のデータを見ないという意味では「ゼロショット」**だが、[[summaries/2023-awq]] は「再構成の過程で較正セットに過適合し、分布外ドメインで学習済み特徴を歪める」と指摘し、視覚言語モデルの実験で **GPTQ が素の RTN より悪くなる**ケースを示した。GPTQ 自身の付録も、C4 の評価について「較正データが C4 の訓練セットから抽出されているので、このタスクは完全なゼロショットではない」と自己申告している。
- **評価がパープレキシティ中心。** 倫理声明で著者自身が「圧縮が二次的な尺度、特にバイアスに与える影響の徹底研究は必要」と述べている。
- **reorder（並べ替え）の工夫**が後続版で追加されており、論文本体の手法だけでは LLaMA 系の一部で不安定（AWQ の Table 4 で LLaMA-7B INT3 の GPTQ が 8.81、GPTQ-R が 6.53 と大きく違う）。

## 実装・運用上の示唆

1. **「計算量を落とす」「メモリ帯域を外す」「数値的に壊れないようにする」は別々の作業である。** GPTQ の 3 ステップはこの 3 つに正確に対応しており、どれか 1 つでも欠けると 175B では動かない。高速化の設計テンプレートとして再利用できる。
2. **貪欲な順序が本当に必要かを疑う。** ステップ 1 は「最適な順序」という直感的に外せなさそうな要素を外して 3 桁稼いだ。大規模では貪欲の利点が薄まる、という観察は他の探索的アルゴリズムにも一般化しうる。
3. **高速化の出所を明示する。** GPTQ が良い論文なのは「3.25 倍」だけでなく「**それはメモリ読み込みの削減であって乗算ではない**」と限界まで書いている点にある。量子化手法を比較するときは常にこの区別を問う（→ [[model-quantization]]）。
4. **ブロック単位のストリーミング量子化。** 6 層ずつ読み込んで量子化し、量子化済みブロックへ入力を通し直す方式は、GPU メモリに載らないモデルを扱う一般的なパターンである。EfficientQAT の Block-AP（→ [[summaries/2024-efficientqat]]）も同じ構造を訓練側に持ち込んでいる。
5. **較正データの分布を評価分布と揃えたか、記録しておく。** GPTQ の C4 の例が示すとおり、揃えると数字は良くなるが「ゼロショット」ではなくなる。

## 用語と略称

- **GPTQ** = OPT モデルファミリの名と PTQ（post-training quantization）の合成（論文の脚注が明記）
- **PTQ** = Post-Training Quantization（訓練後量子化）
- **OBQ / OBS** = Optimal Brain Quantization / Optimal Brain Surgeon（ヘッセ行列の二次情報を使う古典的な枝刈り・量子化の枠組み）
- **RTN** = Round-to-Nearest（最近接丸め）
- **ヘッセ行列（Hessian）** = 損失の二階微分。ここでは $\mathbf{H}_F = 2\mathbf{X}_F\mathbf{X}_F^\top$ で、層入力の相関構造を表す
- **コレスキー分解（Cholesky decomposition）** = 正定値対称行列を $LL^\top$ に分解する数値的に安定な手法
- **不定値（indefinite）** = 正・負の固有値が混在する行列。ここでは数値誤差の蓄積で起こり、更新が誤った方向へ暴走する原因になる
- **dampening（減衰）** = 対角に小さな定数を加えて数値的安定性を確保すること
- **グループ化（grouping）** = 連続する $g$ 個の重みごとに独立なスケール・ゼロ点を持つこと。$g$ が小さいほど精度は上がるがメタデータが増える
- **PPL** = Perplexity（パープレキシティ）
