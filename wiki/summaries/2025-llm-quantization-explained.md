# LLM 量子化の解説

> 原典: [[translations/2025-llm-quantization-explained]] ・ `raw/articles/LLM Quantization Explained.md`
> 著者: joydeep bhattacharjee（Medium, 2025-04-30）

## 一言まとめ

同じ題材を**原理と実装から**扱った記事。丸めの誤差を torch で実測するところから始め、affine 量子化の式、活性の外れ値、STE つき QAT、QLoRA の NF4 まで、**動くコード付きで**降りていく。量子化して**メモリが増えた**失敗までそのまま載せている点が誠実である。

## 背景と問題意識

[[summaries/2025-llm-quantization-guide]] が「どの手法を選ぶか」の記事なら、こちらは「**なぜそうなるのか**」の記事である。同じ 2025 年春の Medium 記事で題材も重なるが、性格がきれいに分かれている。

出発点はハードウェアの対比である。CPU は少数のコアで**低レイテンシの逐次処理**に最適化され、キャッシュ階層（L1/L2/L3）に多くのトランジスタを割く。GPU は膨大なコア（H100 で 16,896）を持ち、**高スループットの並列処理**に最適化され、キャッシュより計算にトランジスタを割いてメモリ遅延は許容する設計をとる。そこから「**GPU の演算はデータ転送が少なく計算に集中するほど速くなる**」という一文が導かれ、これが量子化の動機になる。

## 主張

### 量子化誤差を実際に測る

最も単純な量子化は**丸め**である。文献では **RTN（Round to Nearest）**と呼ばれる。記事は 3×3 のランダム行列を float32 で作って float16 へ落とし、メモリが 36 バイト → 18 バイトになり、絶対誤差の総和が **0.0007** になることを torch で実演する。

**量子化誤差**とは元の値と量子化後の値の差である。記事の指摘で面白いのは、無理数を扱う時点で我々はすでに量子化しているのだから、**情報に形を与える以上いくらかの損失は不可避**だという整理である。問われるべきは誤差の有無でなく「**何が許容できる損失か**」であり、それは自分のドメインとベンチマークでしか決まらない。

### BF16——同じ 16 ビットでも設計思想が違う

**BF16（Brain Float 16）**は Google が深層学習向けに作った形式で、FP16 と同じ 16 ビットだが**指数部が FP32 と同じ 8 ビット**である。したがって動的範囲（表現できる値の広さ）が FP32 と一致し、訓練中のアンダーフロー・オーバーフローに強い。

| 形式 | 符号 | 指数部 | 仮数部 | 動的範囲 |
|---|---|---|---|---|
| float32 | 1 | 8 | 23 | 約 1e-38 〜 3e38 |
| **bfloat16** | 1 | **8** | **7** | 約 1e-38 〜 3e38 |
| float16 | 1 | 5 | 10 | 約 5.9e-8 〜 6.5e4 |

ここで記事は率直な実測を載せる。**同じ丸めをしたとき、BF16 の誤差は FP16 より大きい**（1000 個のランダムテンソルで分布を取り、行列を大きくするほど差が顕著になる）。当然で、仮数部が 7 ビットしかないからである。**BF16 は「精度が高い」形式ではなく「範囲が広い」形式**だという区別が、実測で示されている。実用面では、Llama 3 8B は量子化なしだと 16GB の Colab GPU でメモリエラーになるが、BF16 なら約 12GB で載る。

### 線形（アフィン）量子化——z と s

**線形量子化**は、浮動小数点の範囲を整数の範囲へ線形に写像する。ゼロ点を求めるなら**非対称（asymmetric）**、スケールだけ定義するなら**対称（symmetric）**と呼ぶ。範囲全体をスケールして合わせるので**アフィン量子化**とも言う。**ゼロ点は、浮動小数点のゼロが整数で正確に表現されることを保証するため**に存在する。

$$s = \frac{x_{max} - x_{min}}{q_{max} - q_{min}},\qquad z = q_{min} - \frac{x_{min}}{s}$$
$$q = round\left(\frac{x}{s} + z\right),\qquad x_{dequantized} = s \cdot (q - z)$$

この $z$ を省略すると何が起きるかは、対になる記事 [[summaries/2025-llm-quantization-guide]] の INT8 実例が図らずも示している（値がクランプされて約 20% の誤差になる）。

### 正直な失敗——量子化してメモリが増えた

記事は huggingface の optimum-quanto で Llama-3.2-1B-Instruct を量子化する。結果は **4714 MB → 5716 MB**、つまり**増えた**。著者は原因を、ライブラリが元の重みと量子化値・スケールの**両方**を保持しているためだろうと推測し、`freeze` を呼ぶ必要があるというドキュメントの記述に触れている。

うまくいかなかった実験をそのまま載せているのは二次資料として誠実であり、**「量子化した」と「メモリが減った」は自動的には繋がらない**という実務上の教訓にもなっている。

### 活性の外れ値——SmoothQuant の分析

活性の量子化が重みより難しい理由は、**活性が入力ごとに変わる**ので範囲を予測しにくいことにある。記事は SmoothQuant 論文の分析を引いて、その難しさを 2 点に分解する。

1. **外れ値の大きさ**が大半の活性値の**約 100 倍**ある。per-tensor 量子化では外れ値が最大絶対値の測定を支配してしまい、**外れ値でないチャネルの実効的な量子化水準が 2〜3 段階しか残らない**。
2. **外れ値は固定されたチャネルに持続的に現れる。** あるトークンについてのチャネル間の分散は大きいが、あるチャネルのトークンをまたいだ分散は小さい。つまり**どのチャネルが外れ値かは安定している**。

2 点目は設計に直結する重要な非対称性である。外れ値の位置が安定しているなら、チャネル単位の対処が有効になる。

### ブロック量子化・動的量子化

- **ブロック量子化** — 重みを 64 や 128 のグループへ分け、**ブロックごとに独立に量子化**する。外れ値の影響をブロック内に閉じ込める。代償はスケール係数の保存量で、**ブロックを増やすほど精度は上がるがスケール係数も増える**という明確なトレードオフになる。GGUF の `Q8_0` は「32 要素のブロック ＋ float16 のデルタ ＋ 32 個の int8」という構成。
- **動的量子化** — 較正データを使わず、**実行時に層ごとに z と s を計算**する。層ごとに別々の量子化スキームになる。調整パラメータが少ないので本番パイプラインに組み込みやすく、やや精度も良い傾向があるが、計算時間が増える。累算は桁溢れを避けるため INT16/INT32 で行い、次の層が量子化されていれば INT8 へ戻す。

### QAT と STE——勾配がゼロの関数をどう訓練するか

**QAT** は訓練グラフへ**偽量子化（fake-quantization）**の演算を挿入する。「偽」なのは、量子化した直後に逆量子化するので計算自体は浮動小数点のまま——**量子化ノイズだけを加える**からである。

問題は逆伝播にある。量子化（丸め）の勾配は**未定義な点を除いてほとんど至るところでゼロ**なので、そのままでは学習が進まない。ここで **STE（Straight-Through Estimator, 直通推定器）**を使う。**閾値関数の微分を無視し、恒等関数だったかのように入ってきた勾配をそのまま通す**。名前のとおりの単純な工夫だが、これがなければ QAT は成立しない。

### QLoRA と NF4

**NF4（NormalFloat 4-bit）**は 16 個の量子化水準を持ち、その値は QLoRA 論文で与えられている（`-1.0, -0.696…, -0.525…, …, 0.0, …, 0.722…, 1.0`）。事前学習済みの重みが**ゼロ中心の正規分布に従う**という仮定の下で設計されており、水準がゼロ付近に密に、端に疎に配置されている。

処理は 3 段構えである。(1) **absmax 正規化**で重みを [-1, 1] へ入れる、(2) **ブロック量子化**で外れ値をブロック内に閉じ込める、(3) **二重量子化**でスケール係数自体を量子化し、重みあたり 0.5 ビット → 0.127 ビットまで削る（65B で 3GB）。

実装の細部も面白い。**PyTorch は 4 ビットのデータ型を持たない**ので、bitsandbytes は 4 ビット値を 2 つずつ 1 バイトへパックする（ビットシフトと OR）。記事はこのパッキングを含めて動くコードで示している。

### 選択のワークフロー

huggingface のドキュメントから導いた手順が末尾にある。**動的量子化 → 静的量子化 ＋ 較正 → 評価 → 足りなければ QAT** という順で、「まず安いものから試して、駄目なら高いものへ」という実務的な段階づけになっている。

## 限界・批判的視点

1. **QLoRA を QAT に分類しているのは誤りである。** 記事は「QAT における現在の人気のある手法は QLoRA」と書くが、QLoRA は**ベースモデルを NF4 へ量子化して凍結し、その上で LoRA アダプタを訓練する**手法で、量子化されたベースの重み自体は訓練で更新されない。これは「訓練後量子化されたモデルの上での PEFT（パラメータ効率のよいファインチューニング）」であって、偽量子化と STE で量子化誤差を訓練に織り込む QAT とは別物である。同じ記事が直前で STE つき QAT を正しく説明しているだけに、混同を招きやすい。正しい整理は [[concepts/model-quantization]] に置いた。
2. **BF16 の誤差比較は条件が限定的。** 「BF16 の誤差の方が大きい」は [0,1) 区間の一様乱数を丸めた場合の話である。BF16 の利点は**動的範囲**にあるので、勾配のように非常に小さい値や大きい値が出る場面ではむしろ BF16 が有利になる。記事はこの非対称性を明示していない。
3. **optimum-quanto の実験は原因が推測のまま**である。「おそらくライブラリが両方保持しているから」で止まっており、`freeze` を呼んだ後の再測定が示されていない（本文は freeze を呼んだと書いているが、増加後の数字しかない）。読者が同じ結論に到達できる形にはなっていない。
4. **数値の再現性が低い。** 誤差 0.0007 のような値はランダム初期化に依存し、記事自身も「実行のたびに変わる」と断っている。傾向の説明として読むべきで、ベンチマークとしては扱えない。
5. **査読を経ていない個人ブログ**であり、2025 年 4 月時点のライブラリ（optimum-quanto, bitsandbytes）の挙動に依存する記述が多い。
6. **エージェント固有の観点はない。** 長い trajectory での誤差の累積、ツール呼び出しの JSON 生成のような**構造化出力が量子化にどれだけ脆いか**といった論点は扱われていない。

## 実装・運用上の示唆

- **BF16 と FP16 を「どちらも 16 ビット」で括らない。** BF16 は**範囲**、FP16 は**精度**に振った形式である。訓練の安定性が問題なら BF16、同じ範囲内での細かさが要るなら FP16、という使い分けになる。
- **外れ値がどこに出るかは安定している。** SmoothQuant の 2 つ目の知見（外れ値チャネルはトークンをまたいで一貫している）は、per-tensor でなく**チャネル単位・ブロック単位**の対処が効く理由そのものである。同じ発想は [[summaries/2024-deepseek-v3]] の細粒度量子化にも [[summaries/2024-flashattention-3]] の incoherent processing にも現れる。
- **量子化の前後で必ずメモリを実測する。** 「量子化したのに増えた」はライブラリの挙動次第で普通に起きる。ライブラリのドキュメント（`freeze` の要否など）を読み、実測で確認する。
- **安い手法から順に試す。** 動的量子化 → 静的量子化＋較正 → QAT の順は、コストと効果の順序として素直である。QAT は訓練を伴うので最後に置くのが妥当。
- **STE の考え方は量子化の外でも使える。** 「微分不可能な演算を挟みたいが勾配を通したい」という状況——離散的な選択、ハードな閾値、サンプリング——は広く現れる。

## 用語と略称

- **RTN** = Round to Nearest（最近傍への丸め。最も単純な量子化）
- **BF16 / bfloat16** = Brain Float 16（符号 1・指数部 8・仮数部 7 ビット。FP32 と同じ動的範囲を持つが精度は FP16 より低い）
- **FP16 / float16** = 符号 1・指数部 5・仮数部 10 ビット
- **動的範囲（dynamic range）** = 表現できる値の広さ。指数部のビット数が決める
- **線形量子化 / アフィン量子化（affine quantization）** = 浮動小数点の範囲を整数の範囲へ線形写像する手法
- **スケール（s）/ ゼロ点（z）** = 写像の傾きと切片。ゼロ点は浮動小数点のゼロを整数で正確に表すために置く
- **対称 / 非対称量子化** = ゼロ点を持たない／持つ
- **静的量子化 / 動的量子化** = 較正データで事前にパラメータを決める／実行時に層ごとに決める
- **ブロック量子化（block quantization）** = 重みを 64・128 等のグループに分け、ブロックごとに独立に量子化する
- **absmax 正規化** = テンソルの最大絶対値で割って [-1, 1] へ収める
- **QAT** = Quantization-Aware Training（量子化を意識した訓練）
- **偽量子化（fake-quantization）** = 量子化してすぐ逆量子化する演算。計算は浮動小数点のまま量子化ノイズだけを加える
- **STE** = Straight-Through Estimator（直通推定器。微分がほぼ至るところゼロの演算を、恒等関数とみなして勾配を通す）
- **QLoRA** = NF4 に量子化して凍結したベースの上で LoRA アダプタを訓練する省メモリ・ファインチューニング手法
- **NF4** = NormalFloat 4-bit（重みが正規分布に従う前提で設計された 16 水準の 4 ビット表現）
- **二重量子化（double quantization）** = スケール係数そのものを量子化して追加のメモリを削る
- **SmoothQuant** = 活性の外れ値の困難さを分析し、重み側へ難しさを移す手法を提案した研究
- **per-tensor / per-channel 量子化** = テンソル全体で 1 つのスケール／チャネルごとにスケールを持つ
- **optimum-quanto** = huggingface の量子化ライブラリ
- **PEFT** = Parameter-Efficient Fine-Tuning（少数のパラメータだけ更新する微調整。LoRA がその代表）
