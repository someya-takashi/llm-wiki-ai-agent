# QLoRA: 量子化された LLM の効率的なファインチューニング

> 原典: [[translations/2023-qlora]] ・ `raw/papers/QLoRA_ Efficient Finetuning of Quantized LLMs.md`
> 著者: Tim Dettmers, Artidoro Pagnoni, Ari Holtzman, Luke Zettlemoyer（University of Washington）
> 年・会議: 2023-05・NeurIPS 2023（arXiv:2305.14314）

## 一言まとめ

**65B のファインチューニングを 780GB から 48GB へ**——4 ビットへ量子化して凍結したベースの上で LoRA アダプタだけを訓練し、16 ビットの完全なファインチューニングに一致させた。ただし本論文の後半は量子化を離れ、**LLM-as-a-judge のバイアスを実測した評価方法論の論文**になっている。

## 背景と問題意識

ファインチューニングは LLM を改善する最も効果的な方法の一つだが、**LLaMA 65B の通常の 16 ビットファインチューニングは 780GB 超の GPU メモリを要する**。量子化はメモリを減らせるが、当時の手法は**推論に対してのみ機能し、訓練中には破綻する**とされていた。

ここが本論文の勝負どころである。**量子化された 4 ビットのモデルを、性能劣化なしにファインチューニングできることを初めて実証した。**

### 前提: LoRA と PEFT のメモリの内訳

**LoRA**（Low-rank Adapter）は、事前学習済みの重み $\mathbf{W}$ を固定したまま、低ランクの追加項だけを訓練する:

$$\mathbf{Y}=\mathbf{X}\mathbf{W}+s\,\mathbf{X}\mathbf{L}_{1}\mathbf{L}_{2},\qquad \mathbf{L}_{1}\in\mathbb{R}^{h\times r},\ \mathbf{L}_{2}\in\mathbb{R}^{r\times o}$$

ここで本論文が指摘する非直観的な事実がある。**PEFT のメモリフットプリントの大半は、学習されるアダプタではなく活性の勾配から来る。** 7B の LLaMA を FLAN v2 でバッチサイズ 1 で訓練するとき、LoRA パラメータは **26MB** しか占めないのに **LoRA の入力勾配は 567MB**、4 ビットの基本モデルは 5,048MB。勾配チェックポインティングを使えば入力勾配は 1 系列あたり平均 18MB へ落ちる。

**含意は実務的である**——アダプタのパラメータを削っても総メモリはほとんど減らない。逆に言えば、**総メモリを増やさずにアダプタを増やせる**。これが後の「全線形層にアダプタを入れる」という設計判断の根拠になる。

## 提案手法

3 つの技法からなる。

### (1) 4-bit NormalFloat（NF4）

**分位量子化（quantile quantization）**——各量子化ビンに等しい数の値が入るようにする、情報理論的に最適なデータ型——が出発点である。ただし分位推定は高価で、近似アルゴリズムは**外れ値に対して大きな誤差を持つ。そして外れ値こそ最も重要な値である**。

ここで著者らは前提を使う。**事前学習済みの重みはゼロ中心の正規分布に従う**（付録 F で Shapiro-Wilk 検定により確認。5% 有意で非正規なニューロンは 7.5%＝期待より約 2.5% 多い程度）。分布が量子化定数を除いて固定なら、**分位は共通なので一度計算すれば済む**。

手順は (1) 理論的な $N(0,1)$ の $2^k+1$ 個の分位を推定、(2) $[-1,1]$ へ正規化、(3) 入力を absmax で $[-1,1]$ へ正規化。ゼロの正確な表現を持たせるため、負側 $2^{k-1}$ 個・正側 $2^{k-1}+1$ 個の分位を推定して重複するゼロを 1 つ除く**非対称なデータ型**にする。

### (2) Double Quantization（二重量子化）

精密な 4 ビット量子化には小さなブロックが要るが、ブロックごとのスケール係数がメモリを食う。ブロックサイズ 64 で 32 ビットの定数なら**パラメータあたり 0.5 ビット**。そこでスケール係数自体を量子化する——ブロックサイズ 256 で FP8 へ。

$$32/64 = 0.5 \text{ ビット} \quad\longrightarrow\quad 8/64 + 32/(64\cdot 256) = 0.127 \text{ ビット}$$

**パラメータあたり 0.373 ビットの節約**（65B でおよそ 3GB）。

### (3) Paged Optimizers

NVIDIA の統合メモリを使い、GPU がメモリ不足になるとオプティマイザの状態を CPU RAM へ自動退避し、更新ステップで戻す。**勾配チェックポインティング中のメモリスパイクで OOM になるのを防ぐ**。付録 G によれば、33B は 24GB にぎりぎり収まらず、**paged optimizer なしでは訓練できない**。

### QLoRA 全体

$$\mathbf{Y}^{\text{BF16}}=\mathbf{X}^{\text{BF16}}\,\text{doubleDequant}(c_{1}^{\text{FP32}},c_{2}^{\text{k-bit}},\mathbf{W}^{\text{NF4}})+\mathbf{X}^{\text{BF16}}\mathbf{L}^{\text{BF16}}_{1}\mathbf{L}^{\text{BF16}}_{2}$$

**格納データ型は NF4、計算データ型は BFloat16。** 重みテンソルを使うたびに BF16 へ逆量子化して 16 ビットで行列積する。

そして分類上、最も重要な一文が §3 にある——**「重みの勾配は、16 ビット BrainFloat を使う LoRA のパラメータについてのみ計算する」**。4 ビットの重みは訓練対象ではない。したがって **QLoRA は QAT（量子化を意識した訓練）ではなく、PTQ ＋ PEFT である**（→ [[model-quantization]]、[[parameter-efficient-fine-tuning]]）。

## 実験結果と知見

### 量子化としての結果

- **NF4 > FP4 > Int4。** MMLU 5-shot 平均で BFloat16 53.0、Float4 52.2、**NFloat4+DQ 53.1**。FP4 は一貫して約 1 ポイント遅れる。
- **4 ビット QLoRA は 16 ビットに一致する。** GLUE と Super-NaturalInstructions で、BF16 の完全なファインチューニング・16 ビット LoRA・8 ビット・4 ビットのすべてが同等（例: RoBERTa-large の GLUE で 88.6 / 88.8 / 88.8 / 88.6）。
- **失われた性能はファインチューニングで回復できる。** 「推論のための 4 ビット量子化は性能を落とす」という既知の事実に対し、**量子化後のアダプタ訓練がその損失を完全に回復する**というのが中心的主張である。
- **二重量子化は性能を落とさない**（利得は小さいが、33B/65B を 24/48GB へ収めるための細かい制御を可能にする）。

### PEFT としての結果

**既定の LoRA 設定では 16 ビットに追いつかない。** query と value の attention 射影にだけ LoRA を当てるという標準的な慣行では再現できず、**トランスフォーマーブロックのすべての線形層に LoRA が必要**である。一方で**射影次元 $r$ は性能に無関係**（全層に当てる限り）。前述の「メモリの大半は活性の勾配」がこれを可能にしている。

### チャットボットと評価方法論

Guanaco（OASST1 でファインチューニング）は Vicuna ベンチマークで **ChatGPT の 99.3%**（65B）。33B は 24GB のコンシューマ GPU で 12 時間未満、7B は 5GB で動く。

だが**本論文の後半で最も価値があるのは、評価そのものへの懐疑**である。

- **GPT-4 には強い順序効果がある。** プロンプトの中で**先に現れる応答に高いスコアを付ける**。著者らは両方の順序で平均することを推奨する。
- **GPT-4 は自分を贔屓する。** Table 7 で **GPT-4 の自己評価 Elo 1348 に対し、人間評価では 1176**。勝率にして約 20% の差である。
- **サンプル水準では GPT-4 と人間はあまり一致しない。** システム水準では Kendall $\tau=0.43$ / Spearman $r=0.55$ だが、**サンプル水準の一致は Fleiss $\kappa=0.25$**。人間の注釈者どうしでも $\kappa=0.42$ にとどまり、**強いシステムどうしを比べるとさらに悪化する**。著者ら自身も好ましい応答について意見が分かれたという。
- **絶対スコアは接地できない。** 「10 点満点の 8」が場面をまたいで何を意味するか不明なので、**絶対スコアでなく対比較からの Elo を推奨する**。

### データについての 2 つの発見

- **品質 > サイズ。** 9k サンプルの OASST1 が、450k サンプルの FLAN v2（サブサンプル）をチャットボット性能で上回る。付録 B.4 の統制実験では、**データセットサイズとエポック数を増やしても MMLU は 0.0〜0.5 しか動かないのに、データセット間の差は 1.5〜8.0**——最大 40 倍の開きがある。
- **ベンチマークは部分的に直交している。** **強い MMLU 性能は強いチャットボット性能を意味しない**（FLAN v2 は MMLU で最良・Vicuna で最悪）。性能はファインチューニングデータがベンチマークにどれだけ似ているかに依存する。

## 限界・批判的視点

著者らが挙げるもの:

1. **33B と 65B では 16 ビットの完全なファインチューニングとの一致を確立していない。** 資源コストのため。一致を示したのは 3B までである。
2. **評価ベンチマークが限られる。** BigBench・RAFT・HELM では評価していない。
3. **責任ある AI の評価が限定的。** CrowS でのバイアス評価のみで、**Guanaco は LLaMA 基本モデルのバイアスのパターンに従う**（OASST1 でのファインチューニングはバイアスを減らすように見えるが、他の種類のバイアスは未検証）。
4. **3 ビットや他の PEFT 手法は評価していない。** ただし「量子化後のファインチューニングが失われた情報の大半を回復するように見えるので、はるかに積極的な量子化が可能かもしれない」と示唆している。

読む側で補うべき点:

5. **Guanaco の評価は自分たちが設計した土俵で行われている。** Vicuna ベンチマークは 80 プロンプトしかなく、著者ら自身が「**Vicuna ベンチマークはオープンソースのモデルに有利、OA ベンチマークは ChatGPT に有利**」と認めている。「ChatGPT の 99.3%」はこの前提つきで読む必要がある。
6. **信頼区間が非常に広い。** Table 6 では多くのモデルが性能で重なる。著者ら自身がこれを理由に Elo への移行を推奨しており、**99.3% という数字は論文自身がその後に相対化している**。
7. **RLHF を使っていない。** 交差エントロピーのみで訓練しており、RLHF とのトレードオフは未検証。
8. **「訓練中には破綻する」という前提の扱いが微妙。** QLoRA が示したのは「量子化された重みを**凍結したまま**アダプタを訓練できる」ことであって、「量子化された重みを訓練できる」ことではない。§7 が認めるとおり、**10 億超の規模で量子化された重みを通した逆伝播を研究したのは SwitchBack layers だけ**である。
9. **2023 年 5 月時点のベースライン**（ChatGPT-3.5、Bard、Vicuna 13B）との比較である。

## 実装・運用上の示唆

- **アダプタは全線形層に入れる。$r$ は気にしなくてよい。** 「query と value だけ」という慣行では 16 ビットに届かない。メモリの大半は活性の勾配なので、アダプタを増やすコストは小さい。
- **量子化とファインチューニングは補完的である。** 「4 ビットにすると性能が落ちる」は推論の話であって、**その後にアダプタを訓練すれば回復する**。この非対称性は、量子化のビット数選択の判断を変える（→ 論文自身が「同じ予算なら、パラメータを増やして精度を下げるほうが有益」と述べる）。
- **LLM-as-a-judge を使うなら、順序をシャッフルし、自己評価を疑い、絶対スコアでなく対比較を使う。** 本論文が測った 3 つのバイアス——順序効果・自己贔屓（Elo 1348 vs 1176）・サンプル水準の低い一致（$\kappa=0.25$）——は、エージェントの評価設計にそのまま持ち込める（→ [[agent-evaluation]]）。
- **データは量より適合性。** 9k が 450k に勝つ。そして**ベンチマークの選択が測っているものを決める**——「高校・大学の知識で良い成績を出すモデルが欲しいのか、会話能力が欲しいのか」を先に決めるべきだ、という §8 の問いは、エージェント評価にも同じ形で当てはまる。
- **paged optimizer は「あると便利」ではなく必須の場面がある。** 33B は 24GB にぎりぎり収まらないので、これがないと訓練が始まらない。

## 用語と略称

- **QLoRA** = 4 ビットへ量子化して凍結したベースの上で LoRA アダプタを訓練する手法（PTQ ＋ PEFT であり QAT ではない）
- **LoRA** = Low-rank Adapter（低ランクの追加項だけを訓練する PEFT の代表手法）
- **PEFT** = Parameter-Efficient Fine-Tuning（パラメータ効率のよいファインチューニング）
- **NF4 / NormalFloat 4-bit** = 分位量子化に基づき、ゼロ中心の正規分布に対して情報理論的に最適な 4 ビット表現
- **分位量子化（quantile quantization）** = 各量子化ビンに等しい数の値が入るようにする量子化
- **Double Quantization（二重量子化）** = 量子化定数自体を量子化する。0.5 → 0.127 ビット/param
- **Paged Optimizers** = NVIDIA 統合メモリでオプティマイザ状態を CPU へ自動退避し、メモリスパイクによる OOM を防ぐ
- **格納データ型 / 計算データ型** = 重みを保持する型（NF4）と演算を行う型（BF16）
- **Guanaco** = QLoRA で OASST1 をファインチューニングしたモデルファミリー
- **Elo レーティング** = 対戦相手に対する期待勝率の尺度。絶対スコアの接地問題を避けるために用いる
- **Fleiss κ** = 3 人以上の評価者間一致度の指標
- **Kendall τ / Spearman r** = 順位相関の指標
- **MMLU** = Massively Multitask Language Understanding（57 タスクの多肢選択ベンチマーク）
- **OASST1 / FLAN v2 / Alpaca / HH-RLHF / Chip2 / Longform** = 実験に用いた指示追従データセット群
- **Shapiro-Wilk 検定** = 正規性の統計的検定（付録 F で重みの正規性の確認に使用）
