# DPO — 報酬モデルも RL ループも消す

> 原典: [[translations/2023-dpo]] ・ `raw/papers/Direct Preference Optimization_ Your Language Model is Secretly a Reward Model.md`
> 著者・年・会議: Rafailov, Sharma, Mitchell, Ermon, Manning, Finn（Stanford University）/ 2023 / arXiv:2305.18290（NeurIPS 2023）

## 一言まとめ

RLHF（Reinforcement Learning from Human Feedback, 人間のフィードバックからの強化学習）が最適化している目的関数は、**変数変換ひとつで、選好データ上の二値交差エントロピー 1 本に書き換えられる**ことを示した論文。報酬モデルを別途訓練する必要も、強化学習を回す必要も、訓練中にモデルからサンプリングする必要もなくなる。表題は「言語モデルはひそかに報酬モデルである」。

## 背景と問題意識

[[summaries/2022-instructgpt]] が確立した RLHF は 3 段（SFT → 報酬モデル → PPO）だが、その代償として**訓練中に複数の LM を同時に扱い、方策からのサンプリングを訓練ループの中で回す**必要がある。PPO は policy／critic／reward／reference の 4 モデル構成で、実装も不安定さの管理も難しい。DPO 論文の問題意識は率直で、「相対的な人間の選好を使うことの魅力にもかかわらず、強化学習で大規模言語モデルをファインチューニングすることは依然として大きな実務上の課題である」。

この重さへの回答は、本 wiki の年表上で 3 通り出ている。**DPO（2023）が RL ループごと消す**、**GRPO（[[summaries/2024-deepseekmath]], 2024）が critic だけ消す**、**RLVR（[[summaries/2025-deepseek-r1]], 2025）が報酬モデルを検証器に置き換える**。本論文はその最初のもので、しかも最も過激な削り方をしている。

## 提案手法 — 変数変換ひとつ

<figure>

![](../../raw/assets/2023-dpo/teaser.png)

<figcaption>図1（再掲, 原典の Figure 1）: 既存の RLHF は「選好データ → 報酬モデル → RL で報酬を最大化する方策」の 2 段を踏む。DPO は単純な分類目的関数で、選好を最もよく満たす方策を直接最適化する。これは暗黙の報酬モデルを当てはめており、その最適方策は閉形式で取り出せる。</figcaption>
</figure>

導出は 3 手である。

**第 1 手: KL 制約付き報酬最大化の最適解を書き下す。** RLHF が解いている問題

$$\max_{\pi_\theta}\mathbb{E}\left[r_\phi(x,y)\right] - \beta\,\mathbb{D}_{\mathrm{KL}}\!\left[\pi_\theta \,\|\, \pi_{\text{ref}}\right]$$

の最適解は、ノンパラメトリックな方策クラスの下では閉形式で書ける（付録 A.1 で Gibbs の不等式から導出）:

$$\pi_r(y\mid x) = \frac{1}{Z(x)}\,\pi_{\text{ref}}(y\mid x)\exp\!\left(\tfrac{1}{\beta}r(x,y)\right)$$

参照方策を報酬で指数的に傾けたものである。ただし分配関数 $Z(x)=\sum_y \pi_{\text{ref}}(y|x)\exp(r(x,y)/\beta)$ は全系列にわたる和なので計算できない。ここで従来は行き止まりだった。

**第 2 手: 逆に解いて、報酬を方策で表す。** 対数をとって並べ替えると

$$r(x,y) = \beta\log\frac{\pi_r(y\mid x)}{\pi_{\text{ref}}(y\mid x)} + \beta\log Z(x)$$

**報酬が方策の関数として書けた**。ここが「言語モデルはひそかに報酬モデルである」の中身である。

**第 3 手: 分配関数を消す。** Bradley-Terry モデル（対比較の標準的な確率モデル）は $p^*(y_1\succ y_2\mid x)=\sigma(r^*(x,y_1)-r^*(x,y_2))$ と、**報酬の差にしか依存しない**。上の式を代入すると $\beta\log Z(x)$ は $y$ に依らないので**きれいに相殺される**。残るのは方策と参照方策だけの式で、そのまま最尤推定の目的関数になる:

$$\mathcal{L}_{\text{DPO}} = -\mathbb{E}_{(x,y_w,y_l)\sim\mathcal{D}}\left[\log\sigma\!\left(\beta\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\text{ref}}(y_w\mid x)} - \beta\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\text{ref}}(y_l\mid x)}\right)\right]$$

報酬モデルの訓練損失（[[summaries/2022-instructgpt]] の式）と見比べると構造が同じで、$r_\theta(x,y)$ が $\beta\log\frac{\pi_\theta}{\pi_{\text{ref}}}$ に置き換わっただけである。実装は PyTorch で 10 行ほど（付録 B にコードが載っている）。

### 勾配が何をしているか

$$\nabla_\theta \mathcal{L}_{\text{DPO}} = -\beta\,\mathbb{E}\Big[\underbrace{\sigma(\hat r_\theta(x,y_l)-\hat r_\theta(x,y_w))}_{\text{順序を誤っているほど重い}}\big[\underbrace{\nabla_\theta\log\pi(y_w|x)}_{\text{上げる}}-\underbrace{\nabla_\theta\log\pi(y_l|x)}_{\text{下げる}}\big]\Big]$$

好まれた応答の尤度を上げ、好まれなかった応答の尤度を下げる——だけなら単純な手法（unlikelihood）と同じである。DPO が違うのは、**暗黙の報酬モデル $\hat r_\theta = \beta\log\frac{\pi_\theta}{\pi_{\text{ref}}}$ が順序づけを誤っている事例ほど重みが大きくなる**という動的な重要度重みが入っている点で、著者らはこれが決定的だとする。重みのない素朴版（unlikelihood）は**モデルを退化させる**——付録 Table 3 の実例では、"when when when when …" を数百回繰り返す出力になっている。「好ましくないものの確率を下げる」を無制約にやると壊れる、という具体的な証拠である。

### 理論 — 何を失っていないかの証明

「報酬を $\beta\log\frac{\pi}{\pi_{\text{ref}}}$ の形に限定したら、表現できる報酬が狭まるのでは」という当然の疑問に、§5 が答える。

1. **定義 1**: 2 つの報酬関数が $r(x,y)-r'(x,y)=f(x)$（プロンプトのみの関数だけ違う）なら**同値**とする。
2. **補題 1**: 同値な報酬は同じ選好分布を誘導する（Plackett-Luce 系の**不足決定**——選好データだけでは報酬関数を一意に決められない——という既知の性質）。
3. **補題 2**: 同値な報酬は制約付き RL の下で同じ最適方策を誘導する。
4. **定理 1**: したがって、**すべての報酬の同値クラスは $\beta\log\frac{\pi}{\pi_{\text{ref}}}$ の形で代表できる**。しかも命題 1 でその代表元は一意である。

読み方はこうである——**選好データから決められるのはもともと同値クラスまでで、その中のどれを選ぶかは自由**。DPO はその自由度を「$\pi$ が妥当な確率分布になる（総和が 1）」という条件で使い切り、その結果として分配関数が解析的に扱えるようになる。**表現力を犠牲にせずに計算可能性を得た**という主張である。

### おまけ: PPO はなぜ不安定なのか

§5.2 は同じ枠組みで actor-critic の不安定性を診断する。RLHF の目的関数を control-as-inference で書き直すと、報酬から $\beta\log\sum_y \pi_{\text{ref}}\exp(r_\phi/\beta)$ という項を引く形になる。この項は**参照方策のソフト価値関数**であり、最適解には影響しないが、**これがないと方策勾配の分散が高くなり学習が不安定になる**。従来は価値関数を学習するか、人間の完了をベースラインにした単一サンプルのモンテカルロ推定で近似していた。DPO の再パラメータ化は**ベースラインを一切必要としない**——だから安定する、という説明である。

これは [[summaries/2024-deepseekmath]] の GRPO と読み比べると面白い。**両者は同じ「critic（価値関数）は厄介だ」という診断から出発して、逆方向に解いている**——DPO は RL ごとやめて critic を不要にし、GRPO は RL を残したままグループ内の相対比較で advantage を作って critic を不要にする。

## 実験結果と知見

モデルは GPT-2-large / GPT-J（6B）/ Pythia-2.8B で、**最大 60 億パラメータ**。

**(1) IMDb 感情生成 — 目的関数の最適化効率**。真の報酬関数（感情分類器）が使えるので、報酬と KL のフロンティアを直接描ける。22 回の訓練実行で比較した結果、**DPO のフロンティアは PPO を厳密に支配する**（同じ KL でより高い報酬）。しかも**PPO が真の報酬にアクセスできる場合（PPO-GT）ですら DPO が上回る**。同じ目的関数を最適化しているはずの 2 手法で、直接解いたほうが良い解に届く、という結果である。

**(2) TL;DR 要約**。GPT-4 を評価者とした参照要約に対する勝率で、**DPO 61%（温度 0）vs PPO 57%（最良の温度 0）**。Best of $N$ ベースラインの最大勝率も上回る。加えて **DPO は温度に頑健**で、PPO は高温でベースの GPT-J 水準まで劣化する。人間評価の直接対決でも、温度 0.25 の DPO が温度 0 の PPO より **58%** の割合で好まれた。

**(3) Anthropic HH 単一ターン対話**。**DPO は、データセット中の「選ばれた応答」を上回る唯一の計算効率の良い手法**。計算量の重い Best of 128 と同等以上。なお著者らは、よく知られた提供元の PPO 版 HH モデルも評価したが、**ベースの Pythia-2.8B を上回るプロンプトや温度を見つけられなかった**と報告している。

**(4) 分布外汎化**。TL;DR で訓練した方策を CNN/DailyMail のニュース記事で評価すると、**DPO 0.36 / 0.31 vs PPO 0.26 / 0.23**（温度 0 / 0.25）。PPO はラベルなしの追加プロンプトを使えるのに、DPO はそれなしで上回った。

**(5) GPT-4 ジャッジの検証（§6.4）**。これは手法の結果ではなく**評価方法論の結果**で、本 wiki にとってはむしろこちらが有用である → [[agent-evaluation]]。

| | DPO | SFT | PPO-1 |
| --- | --- | --- | --- |
| GPT-4 (S) 勝率 % | 47 | 27 | 13 |
| GPT-4 (C) 勝率 % | 54 | 32 | 12 |
| 人間の勝率 % | 58 | 43 | 17 |
| GPT-4 (S)-人間 一致 | 70 | 77 | 86 |
| GPT-4 (C)-人間 一致 | 67 | 79 | 85 |
| **人間-人間 一致** | **65** | - | **87** |

**検証の型が学ぶに値する**: ジャッジの一致率を絶対値で見るのではなく、**人間同士の一致率を基準線に置いて比べる**。DPO の比較では人間同士が 65% しか一致しない難しい対戦であり、そこで GPT-4 が 67〜70% 一致していれば「人間の代理として妥当」と言える。PPO-1 の比較は人間同士 87% の易しい対戦で、GPT-4 も 85〜86%。**基準線が動くので、ジャッジの一致率を単独の数字として報告しても意味がない**。

そして**ジャッジのプロンプトの文言が勝率を動かす**。素朴な (S) プロンプトでは GPT-4 は**人間より長く反復的な要約を好む**ので、著者らは "without including unimportant or irrelevant details? A good summary is both precise and concise." を足した (C) プロンプトを用意し、人間により近い勝率が出るこちらを本文の主結果に使った。**同じジャッジ・同じサンプルで、勝率が 47% → 54% 動く**。

## 限界・批判的視点

原典が挙げるもの:

- **最大 6B までしか検証していない**。桁違いに大きなモデルへのスケールは今後の課題。
- **DPO における報酬の過剰最適化（reward over-optimization）の現れ方が不明**。Figure 3 右のわずかな性能低下がそれなのかも分かっていない。**明示的な報酬モデルを消したからといって、報酬ハックの問題が消えたわけではない**ことに著者らは自覚的である。
- **分布外汎化の比較は初期的**。CNN/DailyMail の 1 件のみ。
- **GPT-4 の勝率がプロンプトに影響される**（上記）。

読む側から加える視点:

- **オフラインであることは長所であり制約でもある**。DPO は訓練中にサンプリングしないので安くて安定するが、裏を返せば**選好データセットに存在しない応答は学習の対象にならない**。後の RLVR（[[summaries/2025-deepseek-r1]]）が「長い思考」や自己検証を**創発**させられたのは、まさに訓練中に方策自身が新しい軌跡を生成するオンラインの探索があったからである。「RL ループを消せる」という本論文の結論は、**目的が既存の選好への適合である限りは**正しい。目的が新しい挙動の発見に移った瞬間、消せなくなる——これが本 wiki の年表で DPO の後に RLVR が来る理由である。
- **省けたのは 4 モデル中 2 つ**。PPO の policy／critic／reward／reference のうち、DPO が残すのは policy と reference の 2 つで、参照モデルの対数確率は訓練中ずっと必要になる（事前計算はできる）。「モデルが要らなくなった」ではなく「**報酬モデルの訓練と RL のサンプリングループが要らなくなった**」が正確である。
- **理論の位置づけは後に整理された**。[[summaries/2024-deepseekmath]] の統一パラダイムは、SFT・RFT・DPO・PPO・GRPO をすべて「データソース × 報酬関数 × 勾配係数」の組として単一の勾配式に還元しており、DPO はそこで「オフラインのデータソース × 人間選択の報酬」の組として位置づけられる。DPO の独自性はアルゴリズムの新規性というより、**その組み合わせが閉形式で書けることを示した点**にある。
- **ベースライン実装の一部はすでに歴史になっている**。PPO ベースラインは **TRLX** で実装されているが、TRLX は GitHub 上で 2024-01 を最後に更新が止まっている（2026-08-01 に実測。→ [[summaries/2022-rlhf-illustrated]] の賞味期限節）。「PPO 実装が弱かったのではないか」という再現性の疑義は本論文にも当てはまりうるが、**同じ疑義を後から検証する土台自体がもう保守されていない**。
- **付録に符号の不整合がある**。付録 A.4 の式(21) は本文の式(7) と $y_w$／$y_l$ が入れ替わっており、そこから導かれる勾配の重み係数も本文と符号が逆になる。ar5iv の原文でも同じで、クリップの不良ではない。実装上正しいのは本文側（誤って順序づけているほど重みが大きい）。導出を追って実装する場合は本文の式(8) を採ること。
- **サンプル表が示す「勝った側」の弱さ**。付録 Table 9・10 は GPT-4 が真の応答を選んだ例だが、**Table 10 は GPT-4 の判定自体が誤っている**——「7 足す 2 は？」に対して真の応答は「11」（誤り）、DPO は冗長ながら「nine」（正しい）と答えているのに、GPT-4 は「Response B〔真の応答〕は直接的で正確」と述べて真の応答を選んでいる。著者らがこれをキャプションで明記して収録しているのは誠実だが、**ジャッジは単純な算術ですら間違える**という具体例であり、上の「人間との一致率」という検証の限界も示している（人間の代理として妥当でも、真偽の判定者としては妥当でない）。

## 実装・運用上の示唆

- **選好データがすでにあるなら、まず DPO を試す**。報酬モデルの訓練もロールアウトも要らず、ハイパーパラメータはほぼ既定（$\beta=0.1$、TL;DR のみ $0.5$）で動く。著者らも「$\beta$ を意味のある形で調整していない」と書いている。
- **参照モデルの選び方が効く**。SFT モデルがあるなら $\pi_{\text{ref}}=\pi^{\text{SFT}}$。無い場合は**好まれた完了だけで教師ありファインチューニングして参照モデルを作る**（Preferred-FT）。選好データが生成された分布と $\pi_{\text{ref}}$ の分布シフトを縮めるためで、これを怠ると前提が崩れる。
- **「好ましくないものの確率を下げる」だけの実装をしない**。unlikelihood 型の無制約な尤度最小化は出力を退化させる（付録 Table 3）。DPO の重要度重み $\sigma(\hat r_l - \hat r_w)$ が制動をかけている。
- **温度への頑健性は運用コストに直結する**。PPO は最良温度を外すと大きく劣化するが、DPO は緩やかである。デプロイ時にサンプリング設定を動かす余地が要るなら、この差は無視できない。
- **ジャッジを使うなら、人間同士の一致率を先に測る**。ジャッジ-人間の一致率は、その対戦の難しさ（人間同士の一致率）とセットでしか読めない。そして**ジャッジのプロンプトは中立な物差しではない**ので、文言を変えた版を複数用意して人間の判断に最も近いものを選ぶ、という校正の手順自体を評価設計に組み込む → [[agent-evaluation]]。

## 用語と略称

- **DPO** = Direct Preference Optimization（直接選好最適化）。選好データ上の二値交差エントロピーで方策を直接最適化する手法。
- **RLHF** = Reinforcement Learning from Human Feedback（人間のフィードバックからの強化学習）。
- **PPO** = Proximal Policy Optimization（近位方策最適化）。on-policy・信頼領域型の方策勾配法。
- **SFT** = Supervised Fine-Tuning（教師ありファインチューニング）。
- **Bradley-Terry モデル** = 対比較の標準的な確率モデル。勝つ確率を報酬の差のシグモイドで表す。**差にしか依存しない**ことが DPO の鍵。
- **Plackett-Luce モデル** = Bradley-Terry を 3 つ以上の順位づけへ一般化したモデル。
- **分配関数（partition function）** $Z(x)$ = 確率分布を正規化するための、全候補にわたる和。系列空間では計算不能だが、DPO では相殺されて消える。
- **暗黙の報酬（implicit reward）** $\hat r_\theta = \beta\log\frac{\pi_\theta}{\pi_{\text{ref}}}$ = 方策と参照方策の対数確率比。DPO が明示的な報酬モデルの代わりに使う量。
- **不足決定（under-specification）** = 選好データだけでは報酬関数を一意に決められず、同値クラスまでしか決まらないこと。
- **actor-critic** = 方策（actor）と価値関数（critic）を同時に学習する RL の構成。PPO はこの型。
- **ソフト価値関数** = 報酬を指数的に平均した価値。§5.2 で PPO の分散の原因として現れる。
- **Best of $N$** = $N$ 個サンプリングして報酬モデルが最高と判定したものを返す推論時の手法。強いが推論コストが $N$ 倍。
- **unlikelihood** = 好まれない応答の対数確率を単純に下げる手法。無制約だと出力が退化する。
- **Preferred-FT** = 選好データのうち「選ばれた」完了のみで教師ありファインチューニングしたモデル。
- **reward over-optimization（報酬の過剰最適化）** = 報酬（モデル）の抜け穴を突いて、本来の目的を外れたまま高い報酬を得る現象。reward hacking とほぼ同義。
- **TL;DR / Anthropic HH / IMDb / CNN-DailyMail** = それぞれ Reddit 要約・有用性と無害性の対話・映画レビュー感情・ニュース要約の評価用データセット。
- **TRLX** = 本論文の PPO ベースラインに使われた RLHF ライブラリ（現在は更新停止）。
