# Parameter-Efficient Fine-Tuning（パラメータ効率のよいファインチューニング）

**PEFT**（Parameter-Efficient Fine-Tuning）とは、事前学習済みモデルの重みの大半を**凍結したまま、ごく少数のパラメータだけを訓練する**ファインチューニングの総称である。代表格が **LoRA**（Low-rank Adapter）で、その量子化と組み合わせた版が **QLoRA** にあたる。

エージェントの視点では、PEFT は「**モデルの振る舞いを自分のドメインへ寄せる作業を、単一 GPU の予算で回せるようにする**」層である。ツールの使い方・出力形式・拒否の方針といったエージェント固有の挙動は事後訓練で作り込まれる部分が大きく（→ [[reinforcement-learning-from-human-feedback]]）、その入口のコストを決めるのがここになる。

> **本ページの根拠は現時点で薄い。** [[summaries/2023-qlora]] は QLoRA の論文であって LoRA の論文ではないため、LoRA 本体（Hu ら 2021, arXiv:2106.09685）の原典はまだ取り込まれていない。以下の記述のうち LoRA の定式化と PEFT のメモリ分析は QLoRA §2 と §7 に依拠しており、それを超える主張は置いていない。

## LoRA — 低ランクの追加項だけを訓練する

事前学習済みの射影 $\mathbf{X}\mathbf{W}=\mathbf{Y}$（$\mathbf{X}\in\mathbb{R}^{b\times h}$, $\mathbf{W}\in\mathbb{R}^{h\times o}$）に対し、LoRA は**分解された追加の射影**を足す:

$$\mathbf{Y}=\mathbf{X}\mathbf{W}+s\,\mathbf{X}\mathbf{L}_{1}\mathbf{L}_{2},\qquad \mathbf{L}_{1}\in\mathbb{R}^{h\times r},\ \mathbf{L}_{2}\in\mathbb{R}^{r\times o}$$

$\mathbf{W}$ は固定され、勾配は $\mathbf{W}$ を**通り抜けて** $\mathbf{L}_1, \mathbf{L}_2$ へ届く。訓練されるのは $\mathbf{L}_1, \mathbf{L}_2$ だけである。$r$ は低ランクの次元、$s$ はスカラーのスケール。

## メモリはどこに行っているのか — PEFT の最も反直観的な事実

「パラメータ効率」という名前から、**訓練メモリはアダプタのサイズで決まる**と読みたくなる。そうではない。

[[summaries/2023-qlora]] が 7B の LLaMA を FLAN v2・バッチサイズ 1 で訓練したときの内訳を測っている（LoRA の重みは元モデルの 0.2% 相当という一般的な設定）:

| 構成要素 | メモリ |
|---|---|
| LoRA パラメータ | **26 MB** |
| LoRA の入力勾配 | **567 MB** |
| 入力勾配（勾配チェックポインティングあり） | 1 系列あたり平均 18 MB |
| 4 ビットの基本モデル | 5,048 MB |

**アダプタのパラメータは総メモリのごく一部で、大半は活性の勾配が占める。** ここから 2 つの実務的な帰結が出る。

1. **アダプタを削っても総メモリはほとんど減らない。** 「$r$ を小さくしてメモリを節約する」は効きが悪い。
2. **逆に、総メモリを増やさずにアダプタを増やせる。** これが次の設計判断を可能にする。

そして勾配チェックポインティング（中間の活性を捨てて逆伝播時に再計算する技法）が、この構造では決定的に効く（567MB → 18MB/系列）。

## どこにアダプタを置くか — $r$ より配置

[[summaries/2023-qlora]] の §4 が、実務でそのまま使える 2 つの知見を報告している。

- **query と value の attention 射影にだけ LoRA を当てるという標準的な慣行では、16 ビットの完全なファインチューニングに追いつかない。** 完全なファインチューニングの性能に一致するには、**トランスフォーマーブロックのすべての線形層にアダプタが必要**である。
- **射影次元 $r$ は、全層に当てている限り最終性能と無関係である**（付録 A の Figure 4 で $r \in \{8, 16, 32, 64, 128, 256\}$ を振っても性能が変わらない）。

つまり**チューニングすべきは $r$ ではなく「どの層に置くか」**であり、答えは「全部」である。これは前節のメモリの内訳と整合する——アダプタを増やすコストが小さいからこそ、全層に置くという選択が成立する。

そのほか QLoRA の付録 A/B に実務的な既定値がある: LoRA dropout は小さなモデル（7B/13B）で 0.05〜0.1 が有用だが大きなモデル（33B/65B）ではそうでない、LoRA $\alpha$ は学習率に比例するので固定して学習率を探索する、など。

## QLoRA — 量子化と組み合わせる

**QLoRA は、4 ビット（NF4）へ量子化して凍結したベースモデルの上で LoRA アダプタを訓練する。** 格納データ型は NF4、計算データ型は BF16 で、重みを使うたびに BF16 へ逆量子化して 16 ビットで行列積する。

$$\mathbf{Y}^{\text{BF16}}=\mathbf{X}^{\text{BF16}}\,\text{doubleDequant}(c_{1},c_{2},\mathbf{W}^{\text{NF4}})+\mathbf{X}^{\text{BF16}}\mathbf{L}^{\text{BF16}}_{1}\mathbf{L}^{\text{BF16}}_{2}$$

効果は劇的で、**65B のファインチューニングが 780GB 超から 48GB 未満**になる。33B なら 24GB のコンシューマ GPU に載る。量子化側の技法（NF4・二重量子化・paged optimizers）の詳細は [[model-quantization]] にある。

### QLoRA は QAT ではない

**分類を間違えやすいので明示しておく。QLoRA は PTQ（訓練後量子化）＋ PEFT であって、QAT（量子化を意識した訓練）ではない。**

QLoRA 論文 §3 が明記している——「**重みの勾配は、16 ビット BrainFloat を使う LoRA のパラメータについてのみ計算する**」。4 ビットの重みは一度量子化されたら訓練対象にならない。一方 QAT は、偽量子化（fake-quantization）と STE（Straight-Through Estimator）によって**量子化されたモデル自身の重みを、量子化誤差を織り込みながら訓練する**ものである。

- **いつ量子化するか**: QLoRA は訓練の前に一度きり。QAT は訓練の各ステップで模擬する。
- **何を訓練するか**: QLoRA は別に足したアダプタ。QAT は量子化される重み自身。
- **狙い**: QLoRA は省メモリ・ファインチューニング。QAT は低ビットでの品質維持。

[[summaries/2025-llm-quantization-explained]] は QLoRA を「QAT における現在の人気手法」と紹介しているが、これは誤りである。訂正の詳細は [[model-quantization]] にも置いた。

### Q-PEFT の構造的な弱点 — 低ビットで訓練できても低ビットで配れない

QLoRA を実際に出荷しようとすると、訓練メモリの話だけを見ていては気付かない問題に当たる。

[[summaries/2024-efficientqat]] が指摘している——「**これらの手法は LoRA モジュールを量子化された重みへ統合する必要があり、その結果モデルが FP16 形式へ戻ってしまう**」。アダプタは 16 ビットで訓練されており、$\mathbf{W} + s\mathbf{L}_1\mathbf{L}_2$ をマージした結果は 4 ビットの格子には乗らない。したがってメモリの限られたプラットフォームへ展開するには**もう一度 PTQ をかける必要があり、そこで性能が落ちる**。

この問題に取り組んだ先行研究が 2 つある。

- **QA-LoRA** — LoRA モジュールを再設計し、**ゼロ点へ滑らかに統合できる**ようにする。
- **PEQA** — RTN で低ビット量子化してから**ステップサイズだけをファインチューニング**する。EfficientQAT が「我々のアプローチに最も近い」と認める研究だが、**PTQ 初期化が貧弱**なため 2〜3 ビットでは QLoRA・QA-LoRA に見劣りする。

EfficientQAT の E2E-QP は PEQA と同じ「ステップサイズだけを訓練する」形を取りつつ、**初期化を PTQ から Block-AP（ブロック単位の QAT）に置き換えた**ものと読める。結果、2 ビットの Alpaca 指示チューニングで QA-LoRA を 7B で 5.1%・13B で 4.0%、PEQA を 4.5%・8.7% 上回る。

**実務上の判断**: マージ後も低ビットのまま配る必要があるかどうかで、Q-PEFT と QAT 系のどちらを選ぶかが変わる。**16 ビットで推論するなら QLoRA、4 ビット以下で出荷するなら EfficientQAT 系**、というのがここまでの整理である（→ [[model-quantization]] の「QAT は実用になったのか」）。

### 量子化とファインチューニングは補完的である

QLoRA が示した最も一般性のある結果は、**「推論のための 4 ビット量子化は性能を落とす」という既知の事実が、その後のアダプタ訓練によって覆る**ことである。GLUE と Super-NaturalInstructions で 16 ビットの完全なファインチューニング・16 ビット LoRA・8 ビット・4 ビットがすべて同等になり、MMLU でも NF4＋二重量子化が BFloat16 に一致する（53.1 vs 53.0）。

論文自身の含意は踏み込んでいる——**同じファインチューニング・推論の資源予算のもとでは、基本モデルのパラメータ数を増やしつつ精度を下げるほうが有益である**。さらに §8 は「量子化後のファインチューニングが失われた情報の大半を回復するように見えるので、はるかに積極的な量子化（例: 3 ビット GPTQ ＋ LoRA）が可能かもしれない」と示唆している（未検証）。

## そのほかの PEFT 手法

[[summaries/2023-qlora]] の §7 が挙げる一覧を、根拠として保持できる範囲で記す（いずれも本 wiki に原典は未取得）。

- **prompt tuning / prefix tuning** — 入力側に学習可能な連続ベクトルを付ける
- **埋め込み層の入力のチューニング**
- **IA³** — 隠れ状態をスケールする学習可能なベクトルを入れる
- **完全な層の追加**（アダプタ層）
- **BitFit** — バイアス項だけをチューニングする
- **フィッシャー情報に基づく重みへのマスクの学習**
- 上記の組み合わせ

QLoRA 論文は「**LoRA のアダプタが 16 ビットの完全なファインチューニングの性能に到達できる**ことを示す」に留め、他の PEFT 手法とのトレードオフの探究は今後の課題としている。また §8 で「これらの手法が大きなモデルへスケールするかどうかは不明である。多くの結果がその頑健性を確立しているので LoRA を用いたが、**他のアダプタがより良い性能をもたらすかもしれない**」と述べており、**LoRA が最良だと主張してはいない**点は押さえておくべきである。

## データ側の知見 — 量より適合性

PEFT で何を訓練するかの前に、**何のデータで訓練するか**が効く。[[summaries/2023-qlora]] は 1,000 を超えるモデルを訓練して 2 つの発見を報告している。

- **データセットの品質・適合性 > サイズ。** 9k サンプルの OASST1 が、450k サンプルの FLAN v2（サブサンプル）をチャットボット性能で上回る。付録 B.4 の統制実験では、**サイズとエポック数を増やしても MMLU は 0.0〜0.5 しか動かないのに、データセット間の差は 1.5〜8.0**——最大 40 倍の開きがある。
- **ベンチマークは部分的に直交している。** 強い MMLU 性能は強いチャットボット性能を意味しない。FLAN v2 は MMLU で最良だが Vicuna ベンチマークでは最悪になる。**性能は、ファインチューニングデータが評価ベンチマークにどれだけ似ているかに依存する。**

2 番目は評価設計の問題でもあるので、[[agent-evaluation]] にも接続する。

## 設計論点

- **メモリの内訳を先に測る。** アダプタのサイズを削る前に、活性の勾配がどれだけ占めているかを見る。勾配チェックポインティングのほうが効く場面が多い。
- **アダプタは全線形層に、$r$ は控えめに。** これが QLoRA の実証した既定である。
- **量子化のビット数は「推論の劣化」だけで決めない。** ファインチューニングが後に続くなら、より積極的な量子化が許容されうる。
- **PEFT の比較は未整理のままである。** LoRA が広く使われているのは頑健性の実績によるもので、原理的な優位が示されているわけではない。本 wiki にも LoRA 本体・prompt tuning・IA³ の原典はまだない。
