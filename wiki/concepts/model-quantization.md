# Model Quantization（モデルの量子化）

**量子化（quantization）**とは、モデルの数値を高い精度から低い精度へ写像する圧縮技法である。LLM（Large Language Model, 大規模言語モデル）では重み・活性・KV cache の精度を下げることを指す。

このページを [[llm-inference-optimization]] から切り出したのは、量子化が**推論サービングだけの道具ではない**からである。訓練（FP8 訓練・QAT）、ファインチューニング（QLoRA）、エッジ配布（int2/int4 の QAT 提供）、そしてカーネル実装（FP8 attention）にまたがって現れる汎用の道具であり、[[mixture-of-experts]] を切り出したのと同じ理由が立つ。

エージェントの観点では、量子化は **(a) どのモデルを自分のハードで動かせるか**を決め、**(b) 長い trajectory（エージェントが辿った行動列）の KV cache をどこまで詰められるか**を決め、そして **(c) 多段のツール呼び出しで誤差がどう累積するかという未検証のリスク**を持ち込む。3 番目は本ページで繰り返し出てくる但し書きである。

## 基本 — 何が起きているのか

浮動小数点数は 3 つの部分からなる。**符号ビット**（正負）、**指数部（exponent）**（スケール。表現できる値の**広さ＝動的範囲**を決める）、**仮数部（mantissa / significand）**（有効桁。**細かさ＝精度**を決める）。

| 形式 | 符号 | 指数部 | 仮数部 | 動的範囲 | 位置づけ |
|---|---|---|---|---|---|
| FP32 | 1 | 8 | 23 | 約 1e-38 〜 3e38 | 完全精度 |
| **BF16** | 1 | **8** | **7** | 約 1e-38 〜 3e38 | 範囲に振った半精度 |
| FP16 | 1 | 5 | 10 | 約 5.9e-8 〜 6.5e4 | 精度に振った半精度 |
| FP8 (e4m3) | 1 | 4 | 3 | — | Hopper 以降 |

**BF16 と FP16 を「どちらも 16 ビット」で括らない**のが最初の分かれ道である。BF16 は指数部が FP32 と同じなので動的範囲が一致し、訓練中のアンダーフロー・オーバーフローに強い。一方で仮数部が 7 ビットしかないため、**同じ値を丸めたときの誤差は FP16 より大きい**（[[summaries/2025-llm-quantization-explained]] が 1000 テンソルで実測している）。訓練の安定性が問題なら BF16、狭い範囲での細かさが要るなら FP16、という使い分けになる。

> **この主張の原典は [[summaries/2019-bfloat16]] である**（Kalamkar ら, Intel Labs / Facebook, 2019）。BF16 の実質的な貢献は精度でなく、**FP16 訓練に必須だった loss scaling という調整項目を消したこと**にあった。詳細と 5 領域 8 モデルの実証は [[low-precision-training]] にある。なお **BF16 が常に優れているわけではない**——[[summaries/2023-fp8-lm]] は、master weight のように「狭い範囲で細かい更新」を扱う場面では BF16 が FP16 ＋ テンソルスケーリングに負けることを実測している。**形式の優劣は用途で反転する。**

メモリ見積もりは単純な掛け算である。10 億パラメータなら FP32 で 4.0GB、INT8 で 1.0GB。7B モデルは FP16 で 28GB だが 4 ビットなら 7GB に収まり、コンシューマ GPU に載る。

### 線形（アフィン）量子化

最も基本的な写像は、浮動小数点の範囲を整数の範囲へ線形に送るものである。

$$s = \frac{x_{max} - x_{min}}{q_{max} - q_{min}},\qquad z = q_{min} - \frac{x_{min}}{s}$$
$$q = round\left(\frac{x}{s} + z\right),\qquad x_{dequantized} = s \cdot (q - z)$$

**スケール $s$** が傾き、**ゼロ点 $z$** が切片にあたる。$z$ を持つものを**非対称（asymmetric）**、$s$ だけのものを**対称（symmetric）**と呼ぶ。**ゼロ点の役割は、浮動小数点のゼロが整数で正確に表現されることを保証する**ことにある。

> **よくある誤り**: 非対称なレンジからスケールを計算しておきながらゼロ点を 0 と置くと、範囲の片側がクランプされて大きな誤差になる。[[summaries/2025-llm-quantization-guide]] の INT8 実例がまさにこれで、`scale = (3.8 − (−2.3))/255` と求めながら `zero_point = 0` としたため、3.8 が 159 → 127 へクランプされて復元値が 3.03（約 20% の誤差）になっている。**スケールの求め方とゼロ点の扱いは揃えなければならない。**

最も素朴な量子化は単なる丸めで、文献では **RTN（Round to Nearest）**と呼ばれる。**absmax 正規化**（テンソルの最大絶対値で割って [-1, 1] に収める）もよく使われる前処理である。

## 何を量子化するのか — 3 つの対象

| 対象 | 頻度 | 難易度と理由 |
|---|---|---|
| **重み（weights）** | 最も一般的 | 訓練後は**静的**なので扱いやすい。「4 ビット量子化したモデル」はふつうこれだけを指す |
| **活性（activations）** | 難しい | **入力ごとに変わる**ので範囲が予測できない。較正か実行時計算が要る |
| **KV cache** | 増加中 | 長コンテキストで数 GB を食う。詰めると**コンテキスト長と同時実行数**が伸びる |

エージェント実務では 3 番目の優先度が上がる場面がある。重みの量子化は「モデルを載せる」ための話だが、KV cache の量子化は**多ターンの trajectory と同時に捌けるユーザ数**に直接効くからである。

### 重みのみか、重みと活性か — メモリ帯域の勝ちと演算の勝ち

上表の「重みだけ」と「重みも活性も」は、単なる程度の差ではない。**得られる高速化の出所が違う。**

- **weight-only（W4A16 など。GPTQ, AWQ, QLoRA, GGUF）** — 重みだけを低ビットで**格納**し、計算のたびに FP16 へ逆量子化して 16 ビットで行列積する。速くなるのは**メモリからの読み込み量が減るから**であって、乗算そのものは速くならない。
- **weight-activation（W8A8。SmoothQuant, LLM.int8()）** — 両方を INT8 にして **INT8 の GEMM カーネル**を使う。これは**演算そのもの**が速くなる。

**この区別は推測ではなく、GPTQ 論文が 2 か所で明記している**（[[summaries/2022-gptq]]）——「我々の手法は**メモリ移動の削減**から高速化を得ているのであって、計算量の削減をもたらすものではない」「主流のアーキテクチャでは混合精度オペランド（FP16 × INT4）へのハードウェア支援が欠けているため、**実際の乗算については高速化を提供しない**」。

帰結は運用の判断に直結する。

| | weight-only（W4A16） | weight-activation（W8A8） |
|---|---|---|
| 高速化の出所 | メモリ帯域 | 演算（INT8 Tensor Core） |
| 効く場面 | **バッチ小・生成デコード**（行列-ベクトル積でメモリ律速） | **バッチ大・プリフィル**（行列-行列積で計算律速） |
| 効かない場面 | 大バッチ。GPTQ 自身が「非生成・大バッチでは適用できない。行列を展開してから通常の行列積をすればよい」と書いている | 小バッチではメモリ削減が 8 ビット止まりで、4 ビットに負ける |
| 圧縮率 | 高い（2〜4 ビットまで届く） | 8 ビットで頭打ち |
| 難しさ | 重みの分布は平坦なので比較的易しい | **活性の外れ値**が敵（→ 前節） |

AWQ が weight-only を選ぶ理由も明快で、「ハードウェアの障壁を下げる（必要メモリが小さくなる）だけでなく、**トークン生成も高速化する（メモリ律速のワークロードを緩和する）**」と書いている。**エージェントのように 1 リクエストあたりの生成トークンが長く、バッチが大きくならない用途では weight-only の側に理がある。** 逆に大量の同時リクエストを捌くサービングでは W8A8 の演算の勝ちが効いてくる。

なお 4 ビットで一番速い手法は「一番精度が良い手法」とは限らない。EfficientQAT の Figure 2(a) は、**ベクトル量子化（AQLM, QuIP#）が 2 ビットで最高精度を出すのに、ハードウェア上のオーバーヘッドで推論をむしろ遅くしうる**ことを示している（→ [[summaries/2024-efficientqat]]）。一様量子化が生き残っているのは精度ではなく実装可能性の理由である。

## 外れ値 — 量子化の中心的な敵

低精度で困るのは常に**外れ値（outliers）**である。少数の極端に大きい値がスケール係数を支配し、残りの値の分解能を潰す。

**外れ値は「創発」する。** [[summaries/2022-llm-int8]] が記述的に測っている——トランスフォーマーを 6B から 6.7B へスケールすると**相転移**が起き、外れ値に影響される層が 65% → 100%、系列次元が 35% → 75% へ跳ぶ。この跳躍は量子化手法が破綻する点と**同時に**起こる。しかも外れ値は極端に集中しており、**6.7B・系列長 2048 で 1 系列あたり約 15 万個の外れ値が、わずか 6 個の隠れ次元に収まる**（全特徴の約 0.1%）。

その 0.1% がモデルを支配している。**外れ値の次元をゼロにすると top-1 attention softmax 確率が 40% → 20% へ落ち、検証パープレキシティが 600〜1000% 悪化する**。ランダムな 7 次元を同じように消した場合は、確率の減少が 0.02〜0.3%、パープレキシティの悪化が 0.1%——3 桁以上の差である。**量子化の議論で外れ値が繰り返し出てくるのは、それが「多い」からではなく「少数なのに支配的」だからである。**

同論文のもう一つの発見が、量子化の外にも効く。**創発を予測するのはパラメータ数でなくパープレキシティである。** 外れ値の数はパープレキシティに対して厳密に単調だが、モデルサイズに対しては非単調。パラメータ数を横軸に取ると「突然の相転移」に見えるものが、パープレキシティを横軸に取ると滑らかな指数曲線になる。著者らはここから「**小さなモデルの指数的傾向を研究すれば、相転移の前に創発を検出できるかもしれない**」と述べている（→ [[transformer-architecture]]）。

外れ値の**構造**については、[[summaries/2022-smoothquant]] が 3 点に分解している。

1. **重みは量子化しやすく、活性はそうでない。** 重みの分布は平坦で一様であり、INT8 どころか INT4 でも精度が落ちない。
2. **外れ値の大きさは大半の活性値の約 100 倍**ある。per-tensor 量子化ではこれが最大絶対値の測定を支配し、**外れ値でないチャネルには実効的に 2〜3 段階しか量子化水準が残らない**（チャネル $i$ の実効水準は $2^8 \cdot m_i/m$）。
3. **外れ値は固定されたチャネルに持続的に現れる。** あるトークンについてのチャネル間の分散は大きいが、あるチャネルのトークンをまたいだ分散は小さい。つまり**どのチャネルが外れ値かは安定している**。

3 点目が設計に直結する。外れ値の位置が安定しているなら、**チャネル単位・ブロック単位の対処が効く**。wiki 内で観測される対処は 4 系統に整理できる。

| 路線 | やること | 代表例 |
|---|---|---|
| **分けて保持する** | 外れ値だけ高精度のまま残す | LLM.int8() の混合精度分解 |
| **粒度を細かくする** | スケール係数をブロック／チャネル単位で持つ | ブロック量子化、NF4、DeepSeek-V3 の 1×128 タイル・128×128 ブロック（[[summaries/2024-deepseek-v3]]） |
| **重要な重みを守る** | 少数の顕著な重みを特定して保護する | AWQ（約 1% の salient weights にチャネルごとスケーリング。[[summaries/2023-awq]]） |
| **分布そのものをならす** | 直交回転で外れ値を薄く広げる | incoherent processing（[[summaries/2024-flashattention-3]]）、SmoothQuant |

最後の路線は**出力を変えずに数値的性質だけを変える**点で際立っている。$\mathbf{Q}$ と $\mathbf{K}$ の両方に同じランダム直交行列 $\mathbf{M}$ を掛けると $\mathbf{M}\mathbf{M}^\top = I$ より $(\mathbf{Q}\mathbf{M})(\mathbf{K}\mathbf{M})^\top = \mathbf{Q}\mathbf{K}^\top$ で attention の出力は恒等のまま、各要素は元の要素のランダムな和になるので外れ値がならされる。

### ハードウェアがアルゴリズムを縛る — per-channel の活性量子化が使えない理由

外れ値がチャネルに固定されているなら、**per-channel の活性量子化をすればよい**。[[summaries/2022-smoothquant]] はそれが精度的には正解であることを実測している——OPT の 6.7B〜175B で INT8 per-channel は FP16 とほぼ同一（例: 175B で 71.4% vs 71.6%）なのに対し、per-tensor は 32.3%、per-token は 31.7% と壊滅的である。

**それでも per-channel は使えない。** INT8 の GEMM カーネルは Tensor Core の高スループットな演算列に依存しており、そこへ低スループットの命令を挟むことを許さない。**スケーリングは行列積の「外側の」次元——活性のトークン次元 $T$、重みの出力チャネル次元 $C_o$——にしか置けず、行列積が終わった後にしか適用できない。** 活性の入力チャネル $C_i$ は内側の次元なので、原理的に届かない。

だから SmoothQuant は「per-channel でスケールする」のでなく「**per-channel でスケールした状態を、事前の等価変換で作っておく**」という迂回を取る。**ハードウェアの構造が選択肢を切り落とし、アルゴリズムがその形に合わせて設計し直される**——これは [[llm-inference-optimization]] の FlashAttention 三部作と同じ主題の、量子化版である。

## PTQ と QAT — いつ量子化するか

- **PTQ**（Post-Training Quantization, 訓練後量子化）: 訓練済みモデルに後から適用する。層ごとに補助的な損失（量子化前後の距離）を最小化する貪欲な最適化で、**較正セット**という少数のサンプルしか使わない。安価だがしばしば精度が落ちる。
- **QAT**（Quantization-Aware Training, 量子化を意識した訓練）: 訓練グラフへ**偽量子化（fake-quantization）**の演算を挿入する。「偽」なのは量子化した直後に逆量子化するからで、計算は浮動小数点のまま**量子化ノイズだけを加える**。モデルは量子化誤差を織り込んで学習するので、同じビット数なら PTQ より品質が高い。

QAT には技術的な障害が一つある。**丸めの勾配は未定義な点を除いてほとんど至るところゼロ**なので、そのままでは逆伝播で学習が進まない。ここで **STE（Straight-Through Estimator, 直通推定器）**を使う——**閾値関数の微分を無視し、恒等関数だったかのように入ってきた勾配をそのまま通す**。単純だが、これがなければ QAT は成立しない。STE の発想は量子化の外でも使える（離散的な選択、ハードな閾値、サンプリングなど、微分不可能な演算を挟みながら勾配を通したい場面全般）。

### 較正データセット — ファインチューニングではない

GPTQ・AWQ・静的量子化は、量子化の前に**較正データセット（calibration dataset）**を要求する。代表的なサンプルをモデルに通して活性の統計量（チャネルごとの absmax など）を集め、スケーリング係数と保護すべき重みを決める。

**多くの場合、較正は重みを更新しない。統計を集めるだけである。** 数百〜数千サンプルで足りる。逆に**較正データが本番の入力分布とずれていればスケール係数がずれる**という注意が要る。

> **ただし「較正は統計を集めるだけ」は GPTQ には当てはまらない。** GPTQ は較正データで**再構成誤差を最小化するよう重みを実際に動かす**。これが後に AWQ から批判される点で、**過適合が現実の問題になる**（次項）。手法ごとに「較正が何をするのか」——統計収集か、重みの最適化か——を確認する必要がある。

#### 較正データへの過適合 — AWQ vs GPTQ

[[summaries/2023-awq]] が測っている。Pile の PubMed Abstracts と Enron Emails を較正／評価に交差させると:

| | 較正と評価の分布がずれたときの PPL 悪化 |
|---|---|
| **AWQ** | **0.5〜0.6** |
| GPTQ | 2.3〜4.9 |

さらに決定的なのが視覚言語モデルでの結果である。OpenFlamingo-9B の COCO キャプショニング（INT4-g128、32-shot CIDEr の劣化）で **RTN −4.57 / GPTQ −6.72 / AWQ −1.17**——**GPTQ が素の最近接丸めより悪い**。再構成ベースの手法は、較正と違う分布では丸めに負けうる。

原因は設計にある。**AWQ が較正から取るのは「チャネルごとの平均活性スケール」という 1 つの統計量だけ**なので、過適合しようがない。だから較正データも GPTQ の 10 分の 1（16 系列 vs 192 系列）で済む。一方 GPTQ は較正データ上の再構成損失を最適化するので、そのデータの特性を取り込んでしまう。

**判断の指針**: 汎用モデルを量子化して未知のドメイン・モダリティへ出すなら、ベンチマーク上の 0.1 PPL より**分布がずれたときの劣化幅**を見る。逆に用途が固定されていて本番分布の較正データが取れるなら、GPTQ の再構成は素直に効く。

なお両者は排他ではない。**INT2-g64 では AWQ + GPTQ の組み合わせが最良**である（OPT-13B で GPTQ 単体 16.74 → 13.25）。「顕著な重みを守る」と「誤差を補償する」は直交する操作だからである。

較正を使わない選択肢が**動的量子化**で、実行時に層ごとに $z$ と $s$ を計算する。調整パラメータが少なく本番パイプラインに組み込みやすいが、計算時間が増える。

### QAT は実用になったのか

**2024 年に答えが変わった論点である。**

長らく QAT の位置づけは「精度は最良だがコストが法外」だった。本 wiki の原典もそう書いている——AWQ（2023）は「QAT は訓練コストが高いため実用的でない」、GPTQ（2022）は「モデルの再訓練は数十億パラメータのモデルには極端に高価」。QAT の代表例 **BitNet b1.58** はほぼ無損失の三値量子化を達成したが、**事前学習データセット全体でのゼロからの再訓練**を要し、検証されたのは 3B モデル・1,000 億トークンまでだった。

[[summaries/2024-efficientqat]] がこれを覆した。要点は**訓練を 2 段に割る**ことにある。

1. **Block-AP**（全パラメータのブロック単位訓練） — トランスフォーマブロックを 1 つずつ、ブロック単位の再構成損失で、ステップサイズ $s$・ゼロ点 $z$・重み $\mathbf{W}$ の**すべて**を訓練する。LLM 全体を一度にメモリへ載せる必要がない。
2. **E2E-QP**（量子化パラメータの端から端までの訓練） — 量子化重みを**固定**し、ステップサイズ $s$ だけ（グループサイズ 64 で全体の約 1.5%）を端から端まで訓練する。

**同時に満たせない 2 つの要求——「全パラメータを訓練したい」と「モデル全体を見渡したい」——を、時間軸で分離している。** 結果:

| Llama-2 | 合計訓練時間 | E2E-QP のメモリ（2 ビット） |
|---|---|---|
| 7B | 4.8h | 5.6GB |
| **70B** | **40.9h** | **34.2GB** |

すべて **A100 1 枚**である。2 ビットの Llama-2-70B でゼロショット正解率の劣化は 3% 未満（69.48 vs 72.41）。

**「全部訓練する」が最良だった、という反直感的な発見**も重要である。従来の QAT 系手法は過適合を防ぐために訓練対象を絞ってきた（丸めパラメータのみ、クリッピング閾値のみ、ステップサイズのみ）が、これらは整数重みの更新範囲を $(-1,+1)$ に制約する正則化として働き、**解空間を狭めて性能を頭打ちにしていた**。EfficientQAT は制約を外し、代わりに**訓練サンプルを 128 → 4096 に増やすだけで**過適合に対処した（訓練損失と検証損失の差 1.07 → 0.06）。しかも $\mathbf{W}$ を直接訓練するほうがメモリは小さい（丸めパラメータの複製が要らない）。

**ただし QAT を使うべき条件は狭い。** 著者自身が付録で書いている——「**4 ビットのグループ単位量子化では、GPTQ・AWQ、さらには最も単純な RTN が同等の性能をより速く達成する**」。

| ビット数 | 推奨 |
|---|---|
| 4 ビット | **PTQ で十分**（RTN でさえ健闘する） |
| 3 ビット | PTQ と QAT の差が開き始める（正解率で約 0.5〜3%） |
| **2 ビット** | **QAT の領域**（Llama-2-7B で AutoRound を 5% 上回る） |

もう一つ、QAT にはビット数以外の理由もある。**Q-PEFT（QLoRA 系）は低ビットで訓練できても低ビットで配れない**——LoRA アダプタを量子化重みへマージするとモデルが FP16 へ戻り、出荷にはもう一度 PTQ が要る。E2E-QP はステップサイズだけを訓練するので**終始低ビットのまま**であり、この問題が生じない（→ [[parameter-efficient-fine-tuning]]）。

残る限界は、**2 ビットにまだ 3〜4% の差があること**、そして **Llama-3 のように訓練が行き渡ったモデル（15T トークン）は Llama-2（2T）より量子化しにくく、これは QAT でも解消しない**ことである。冗長性の少ないモデルほど圧縮の余地が小さい。

そして最後に分類の注意——**QLoRA は QAT ではない**（次項）。

## 代表的な手法

- **LLM.int8()**（[[summaries/2022-llm-int8]]） — 2 つの部品からなる。**(a) vector-wise 量子化**: 行列積を独立な内積の列と見なし、隠れ状態の**各行**と重みの**各列**に別々の absmax スケール係数を持たせる（逆量子化は外積で一括）。**(b) 混合精度分解**: 大きさが閾値 $\alpha=6.0$ を超える外れ値を含む特徴次元だけを 16 ビットの行列積へ分離し、残り 99.9% を 8 ビットで計算する。13B までは外れ値の次元が 7 以下なので追加メモリは約 0.1%。**なぜ vector-wise だけでは足りないのか**が明快である——vector-wise は隠れ状態の「行（系列次元）」をスケールするが、**外れ値は「列（特徴次元）」に生じる**。軸が直交しているので原理的に届かない。175B まで劣化ゼロを達成した初の手法。ただし**速度は別問題**で、モデル次元 4096 以下では FP16 より遅い（後述）。
- **bitsandbytes** — LLM.int8() と NF4 を提供するライブラリ。LoRA / QLoRA での省メモリ・ファインチューニングの標準。**なお 8 ビット側（LLM.int8()）と 4 ビット側（NF4 のブロック量子化）は別物である**——「64 要素ブロックごとにスケール係数」は 4 ビット側の性質で、LLM.int8() の眼目は vector-wise ＋ 外れ値分解にある。
- **SmoothQuant**（[[summaries/2022-smoothquant]]） — 外れ値を**分離するのでなく移す**。活性を per-channel の平滑化係数 $\mathbf{s}$ で割り、重みを逆方向に掛ける $\mathbf{Y}=(\mathbf{X}\,\text{diag}(\mathbf{s})^{-1})\cdot(\text{diag}(\mathbf{s})\mathbf{W})$ という**数学的に等価な変換**で、活性の難しさを重みへ移す。移す量は **migration strength** $\alpha$ で制御し、$\mathbf{s}_{j}=\max(|\mathbf{X}_{j}|)^{\alpha}/\max(|\mathbf{W}_{j}|)^{1-\alpha}$（OPT/BLOOM は 0.5、GLM-130B は 0.75、LLaMA は 0.8）。係数は先行層のパラメータへオフラインで融合できるので実行時コストはゼロ。これにより**重みと活性の両方を INT8 にする W8A8** が成立し、INT8 GEMM カーネルが使えるようになる。
- **NF4（NormalFloat 4-bit）** — 事前学習済みの重みが**ゼロ中心の正規分布に従う**という仮定の下で設計された 16 水準の 4 ビット表現。水準がゼロ付近に密、端に疎に配置されている。QLoRA 論文が具体値を与えている。
- **double quantization（二重量子化）** — ブロックごとのスケール係数**そのもの**を量子化する。64 要素ブロックの 32 ビットスケール係数は重みあたり 0.5 ビットを追加するが、これを 256 個ずつまとめて 8 ビットへ落とすと **0.127 ビット**まで下がる。65B モデルで **3GB** の節約。
- **GPTQ**（[[summaries/2022-gptq]]） — **層ごと**に $\arg\min_{\widehat{W}}\lVert WX-\widehat{W}X\rVert_2^2$ を解き、重みを 1 つ量子化するたびにヘッセ行列 $\mathbf{H}_F=2\mathbf{X}_F\mathbf{X}_F^\top$ の情報で残りの重みを補償更新する（土台は OBQ = Optimal Brain Quantization）。**貢献はアルゴリズムでなく、それを 3 桁速くした 3 つの工夫にある**。**(1) 任意順序**——貪欲な順序の利点は大きな層では消えるので全行を同じ順序で処理する。すると $\mathbf{H}_F^{-1}$ が全行共通になり、更新回数が重みごとから列ごとへ落ちて $O(d_{\text{row}}d_{\text{col}}^{3}) \to O(\max\{d_{\text{row}}d_{\text{col}}^{2},d_{\text{col}}^{3}\})$。**(2) 遅延バッチ更新**——計算対メモリアクセス比が低くメモリ帯域で詰まるので、$B=128$ 列単位にまとめる（理論計算量は不変、実測 1 桁）。**(3) コレスキー再定式化**——数十億パラメータを超えると $\mathbf{H}_F^{-1}$ が不定値になって更新が暴走するため、必要な行を最初にコレスキー分解で前計算する（＋対角に平均の 1% の減衰）。結果、**175B を A100 1 枚・4 時間**で 3〜4 ビット化。**較正は C4 の 128 断片のみ。** 重み 4 ビット、活性 FP16。グループ化との相性が良く、g8 なら三値量子化まで届く（OPT-175B で PPL 9.20）。
- **AWQ**（Activation-aware Weight Quantization, W4A16。[[summaries/2023-awq]]） — **「どの重みが大事か」を重みでなく活性で決める**。INT3-g128 の OPT-6.7B で、1% を FP16 に残したときの PPL は**活性基準 11.39 / 重みノルム基準 22.37 / ランダム 24.23**（無処理 23.54、FP16 10.86）——**「大きい重みが重要」はランダム選択と大差ない**。理屈は $y=wx$ で誤差の影響が $\Delta w\cdot x$ だから。ただし混合精度は避けたいので、$w$ に $s>1$ を掛けて $x$ を $1/s$ で割る等価変換に置き換える（誤差比は $\frac{\Delta'}{\Delta}\cdot\frac{1}{s}$ で、$\Delta'\approx\Delta$ なら $1/s$ に縮む）。**ただし $s$ は上げすぎてはいけない**——$s=4$ ではグループの 21.2% で $\Delta$ が動き、**守らない側のチャネルの誤差が増幅されて** PPL が悪化する（最良は $s=2$）。実際には探索空間を $\mathbf{s}=\mathbf{s_X}^{\alpha}$（$\alpha\in[0,1]$）に縛り、**グリッド 20 点**で終わらせる。**逆伝播も回帰もない。** 較正から取るのは「チャネルごとの平均活性スケール」1 つだけで、これが汎化を生む（後述）。
- **EfficientQAT**（[[summaries/2024-efficientqat]]） — QAT を 2 段に割ってコストを下げる。**Block-AP** がトランスフォーマブロック単位で $s$・$z$・$\mathbf{W}$ の**全部**を訓練し、**E2E-QP** が量子化重みを固定してステップサイズ $s$ のみ（全体の約 1.5%）を端から端まで訓練する。**Llama-2-70B の 2 ビット化が A100 1 枚・41 時間・訓練メモリ 34.2GB**。後述。
- **GGML / GGUF** — **CPU 推論**のためのモデル形式。**k-Quant** 方式で重みをブロックへ分け、重要度に応じてビット幅を変える（q2\_k, q5\_0, q8\_0 など）。`Q8_0` は「32 要素ブロック ＋ float16 のデルタ ＋ 32 個の int8」。動かすには **llama.cpp** が要る。
- **QLoRA** — 後述。分類に注意が要る。

### QLoRA は QAT ではない

**QLoRA は PTQ ＋ PEFT であって、QAT ではない。** [[summaries/2025-llm-quantization-explained]] は QLoRA を「QAT における現在の人気手法」と紹介しているが、これは分類の誤りなのでここで正しておく。

QLoRA の構造は次のとおりである。

1. ベースモデルを **NF4 へ量子化して凍結する**（訓練後の一回きり。以後この重みは更新されない）。
2. その上に **LoRA アダプタ**（低ランクの追加パラメータ）を載せ、**アダプタだけを** BF16 等で訓練する。
3. 前方計算のときに NF4 の重みを逐次逆量子化して使う。

QAT の定義は「**偽量子化と STE によって、量子化されたモデル自身の重みを、量子化誤差を織り込みながら訓練する**」ことである。QLoRA では量子化された重みは訓練対象ではない。訓練されるのは別に足したアダプタであり、量子化誤差は「補償される」というより「アダプタが吸収する」形になる。目的も違い、QAT は**低ビットでの品質維持**、QLoRA は**限られた GPU メモリでのファインチューニング**を狙う。

**原典が明記している。** [[summaries/2023-qlora]] §3 は「**重みの勾配は、16 ビット BrainFloat を使う LoRA のパラメータについてのみ計算する**」と書いており、4 ビットの重みが訓練対象でないことに疑問の余地はない。詳細は [[parameter-efficient-fine-tuning]] にある。

なお QLoRA が示した最も一般性のある結果は、**量子化とファインチューニングが補完的である**ことである——「推論のための 4 ビット量子化は性能を落とす」という既知の事実が、その後のアダプタ訓練によって覆る。論文自身の含意は踏み込んでいて、**同じ資源予算なら基本モデルのパラメータ数を増やしつつ精度を下げるほうが有益**であり、さらに「量子化後のファインチューニングが失われた情報の大半を回復するように見えるので、**3 ビット GPTQ ＋ LoRA のようなはるかに積極的な量子化も可能かもしれない**」（未検証）と示唆している。

同じ記事が直前で STE つき QAT を正しく説明しているだけに混同しやすいが、両者は**いつ量子化するか**も**何を訓練するか**も異なる。

### そのほか、二次資料で見かける誤り

本ページの根拠にした 2 記事には、以下の誤りがある。実務で参照するときの注意として記しておく。

- **「NF8」という形式は存在しない。** [[summaries/2025-llm-quantization-guide]] は LLM.int8() を「nf4 の代わりに nf8 を使う」と説明し、付表にも `uses nf4,nf8` と書いているが、LLM.int8() は NormalFloat ではなく **INT8 ＋ 外れ値の混合精度分解**である。NormalFloat は QLoRA が 4 ビット向けに導入したもので、8 ビット版は定義されていない。
- **LLM.int8() の特徴づけの混同。** 同記事は「64 要素ブロックごとにスケール係数」を 8 ビットの説明に置いているが、これは bitsandbytes の**4 ビット側**（NF4 のブロック量子化）の性質である。LLM.int8() の眼目はベクトル単位の量子化と外れ値分解にある。

## 「量子化＝高速化」ではない

最も誤解されやすい点である。**量子化はほぼ常にメモリを減らすが、低レイテンシは保証されない。** 遅くなりうる状況が 4 つある（[[summaries/2025-llm-quantization-guide]]）。

1. **逆量子化のオーバーヘッド** — 多くの手法は INT4/INT8 で**格納**するが計算は FP16/BF16 で行うので、推論のたびに逆量子化の計算が乗る。
2. **ハードウェア支援の欠如** — GPU/CPU に低精度演算の専用回路がなければ、低ビット化の恩恵を受け取れない。
3. **最適化されていない推論エンジン** — 行列積のたびに逆量子化する実装だと遅くなる。
4. **小さなモデル** — 逆量子化のオーバーヘッドがメモリ節約を上回る。

これは [[llm-inference-optimization]] の主題群——「FLOPs ≠ wall-clock」「律速はどこにあるか」——の量子化版にあたる。**メモリと速度は別の目的関数である。**

**一次資料に直接対決の数字がある。** [[summaries/2022-smoothquant]] の Table 10（OPT-13B、系列長 256、バッチ 4）:

| | レイテンシ |
|---|---|
| FP16 | 152.6 ms |
| **LLM.int8()** | **237.1 ms**（FP16 の 1.55 倍遅い） |
| SmoothQuant-O3 | **112.1 ms**（FP16 の 1.36 倍速い） |

**精度では両者とも FP16 に一致する**（OPT-175B の平均で 66.7% vs 66.8%）のに、速度は正反対である。原因は混合精度分解にあり、疎な列を抜き出して別の行列積にするので GEMM カーネルの規則的な流れが崩れる。[[summaries/2022-llm-int8]] 自身も §3.4 で「量子化のオーバーヘッドは 67 億パラメータ未満のモデルでは推論を遅くしうる」と認めており、付録 D の実測では**モデル次元 2560（2.7B 相当）で 0.64x、4096（6.7B 相当）でも 0.86x** と 1.0 を割る。

したがって、量子化手法の比較表を読むときは**精度の列だけを見てはいけない**。そして LLM.int8() の価値は速度でなく「**これまで載らなかったモデルが載る**」ことにある——8×RTX 3090（24GB）で OPT-175B/BLOOM が動く、というのが同論文の実質的な貢献である。

さらに、**「量子化した」と「メモリが減った」も自動では繋がらない**。[[summaries/2025-llm-quantization-explained]] は optimum-quanto で Llama-3.2-1B を量子化して **4714 MB → 5716 MB と増える**結果を報告している（ライブラリが元の重みと量子化値の両方を保持していたためと推測されている）。**前後で必ず実測する。**

## 訓練側の量子化

推論だけの話ではない。

> **訓練そのものを低精度で回す話は、2026-08-02 に独立した概念ページ [[low-precision-training]] へ切り出した。** BF16（2019）→ FP8（2023）→ FP4（2025）の系譜、技法のカタログ、「どこを低精度にしないか」の規律、否定的結果の一覧はそちらにある。**目的が違う点に注意**——低精度訓練は**訓練コストを下げる**もので成果物は高精度のモデルでよく、QAT は**低ビットで配れるモデルを作る**ものである。両者は直交する。本節は概観に留める。

- **FP8 訓練**（[[summaries/2024-deepseek-v3]]）— 671B の MoE を FP8 混合精度で訓練しきり、BF16 比の相対 loss 誤差を 0.25% 未満に収めた公開記録。要点は**どこを FP8 にしないか**を先に決めること（埋め込み・出力ヘッド・MoE ゲーティング・正規化・attention は高精度のまま）、**細粒度量子化**（活性 1×128 タイル、重み 128×128 ブロック）、そして**否定的結果の公開**（活性の勾配をブロック単位で量子化すると 16B モデルが約 300B トークンで発散する）。
- **FP8 カーネル**（[[summaries/2024-flashattention-3]]）— attention を FP8 で計算するためのレイアウト適合と、block quantization ＋ incoherent processing による精度対策。per-tensor ベースライン比で RMSE 2.6 分の 1。ただし**効いているのはほぼ incoherent processing だけ**である（ブロック量子化を外しても誤差はほぼ変わらない）。
- **提供側の QAT**（[[summaries/2026-gemma-4]]）— 事後量子化でなく訓練段階で量子化を引き受け、int2/int4 混合の重みを配布する。E2B は bf16 4.6GB → **0.8GB**。「量子化はデプロイ時の後処理」という前提を崩す動き。
- **KV cache の圧縮**（[[summaries/2026-deepseek-v4]]）— 量子化とは別路線だが目的は同じで、学習された圧縮とスパース選択（CSA/HCA）で 1M コンテキストの KV cache を一般的な BF16 GQA8 構成の約 2% にする。
- **FP4 訓練**（[[summaries/2025-nvfp4-pretraining]]）— 12B を **10T トークン、4 ビット**で訓練しきった公開記録。ここまで来ると形式単体では成立せず、**Random Hadamard 変換・確率的丸め・2D スケーリング・選択的高精度層**を全部載せて初めて収束する。詳細は [[low-precision-training]]。

## 選び方

| 状況 | 推奨 |
|---|---|
| CPU で動かす | **GGUF**（llama.cpp） |
| NVIDIA GPU で 4 ビット | **GPTQ** または **AWQ**（RTN でも健闘するので、まずそこから測る） |
| 未知のドメイン・モダリティへ出す | **AWQ**（較正データへの過適合が小さい） |
| 用途が固定・本番分布の較正データがある | **GPTQ**（再構成が素直に効く） |
| **2〜3 ビットまで落としたい** | **EfficientQAT**（QAT）／ INT2 なら AWQ + GPTQ の併用も |
| 大バッチのサービングで演算を速くしたい | **SmoothQuant**（W8A8） |
| 小バッチ・長い生成でメモリ帯域を稼ぎたい | weight-only（W4A16） |
| 少ない GPU メモリでファインチューニング | **bitsandbytes** ＋ LoRA / **QLoRA** |
| ファインチューニング後も低ビットで配りたい | **EfficientQAT の E2E-QP**（QLoRA はマージで FP16 へ戻る） |
| 精度最優先・ハードに余裕がある | 量子化しない（FP16 / BF16） |
| エッジ・モバイル | 提供側の **QAT** 済み重み（あれば） |

手順としては、**安いものから順に試す**のが素直である——動的量子化 → 静的量子化＋較正 → 評価 → 足りなければ QAT。QAT は訓練を伴うので最後に置く。**目安は「4 ビットなら PTQ、2〜3 ビットなら QAT」**である。

## 設計論点

- **どのビット幅まで落とすかは、ベンチマークでなく自分のタスクで決める。** 公表される「精度 ≈99.5% を維持」といった数字は特定ベンチマークのものであり、**エージェントの多段ツール呼び出しや長い CoT での累積影響は別に検証しなければならない**（[[summaries/2026-llm-optimization-guide]] も同じ但し書きを置いている）。とくにツール呼び出しの JSON のような構造化出力が低ビット化にどれだけ脆いかは、本 wiki の原典群では誰も測っていない。
- **量子化を避けるべき場合もある。** 精度が決定的に重要なとき、ゼロから訓練するとき、FP16/BF16 で載るだけのメモリがあるとき、品質のわずかな低下も許容できないとき。
- **スケール係数の保存量とのトレードオフ。** ブロックを細かくするほど外れ値の影響は減るが、保存すべきスケール係数が増える。二重量子化はこのトレードオフ自体を一段圧縮する手である。
- **較正データの分布を本番に合わせる。** 較正は（多くの手法では）重みを更新しないが、スケール係数は較正データの活性分布で決まる。GPTQ のように較正データで重みを最適化する手法では、過適合が実際の劣化として現れる。
- **重要度の代理指標はランダム選択をベースラインにして検証する。** AWQ の Table 1 で「重みのノルムで選ぶ」がランダム選択と同程度だったのは、機械学習で最も広く使われる代理指標が特定の設定では機能しないという実例である。枝刈り・特徴選択でも同じ検証をすべきである。
- **「守る」操作の副作用を同時に測る。** AWQ のスケーリングは $s=4$ で顕著チャネルの誤差を減らし続けるのに全体性能は悪化する。**保護対象の指標だけを見ていると最適点を通り過ぎる。**
- **高速化の出所を明示して比較する。** 「3.25 倍」がメモリ読み込みの削減なのか演算の削減なのかで、適用できる場面が変わる（前述の weight-only / weight-activation）。
